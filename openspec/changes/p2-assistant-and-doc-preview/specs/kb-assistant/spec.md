## Purpose

定义知识库小助理：一个挂载在知识库侧的助理 Agent，帮助用户把素材整理成结构化 Markdown。边界核心为两条铁律——**对 Vault 严格只读**（产出一律进工作台自己的草稿区，人工确认才落地）；**不参与电商工作流**（不接任务、不出现在任务阶段与播报中，工作流班组仍是文案/设计师/主管三人）。

## ADDED Requirements

### Requirement: 助理 Agent 实体

系统 SHALL 提供一个小助理 Agent 实体（角色「助理」，默认模型 deepseek-chat），与既有文案/设计师/主管并列存储于同一 Agent 体系。小助理 SHALL 出现在以下 Agent 相关界面：Agent 状态页（含其执行统计）、聊天面板的私聊对象列表（用户可与小助理私聊）、以及 Agent 设置弹窗（人设/模型配置，复用既有能力）。知识库总览带的小助理入口 SHALL 展示该实体的真实 Agent 卡（头像 + 状态点 + 名字 + 角色）。

#### Scenario: Agent 状态页显示小助理

- **WHEN** 用户打开 Agent 状态页
- **THEN** 页面包含小助理的状态卡（头像、名字、角色「助理」、在线状态与执行统计），统计只计其自身调用

#### Scenario: 可与小助理私聊

- **WHEN** 用户打开聊天面板
- **THEN** 私聊对象列表包含小助理，点击后可与其会话

#### Scenario: 可配置小助理

- **WHEN** 用户在总览带或状态页打开小助理的设置
- **THEN** 打开与其他 Agent 相同的设置弹窗，可编辑人设与模型并保存

#### Scenario: 总览带展示真实 Agent 卡

- **WHEN** 小助理实体存在且用户打开知识库页
- **THEN** 总览带小助理位渲染其真实 Agent 卡（与工位卡同形态），不再是「开发中」占位

### Requirement: 工作流严格隔离

小助理 SHALL NOT 参与电商工作流：工作流的任务派发、阶段负责 Agent 映射、任务详情阶段条、以及群聊播报署名 SHALL NOT 出现「助理」角色；工作流班组 SHALL 保持文案/设计师/主管三人。工位栏 SHALL NOT 渲染小助理（工位栏语义 = 工作流班组）。小助理的任务派发入口 SHALL NOT 存在。

#### Scenario: 工位栏不显示小助理

- **WHEN** 小助理实体存在且用户打开任务看板
- **THEN** 工位栏仍只显示文案/设计师/主管三张 Agent 卡，小助理不出现在工位栏

#### Scenario: 阶段条与派发不含小助理

- **WHEN** 用户查看任意任务的详情阶段条，或工作流推进任务
- **THEN** 各阶段负责 Agent 仍为文案/设计师/主管，「助理」不出现在任何阶段上，也没有任何任务会被派发给小助理

#### Scenario: 群聊播报不含小助理

- **WHEN** 工作流产生群聊播报消息
- **THEN** 播报署名仍按既有角色映射（美美/平平/波波），小助理不出现在播报中

### Requirement: 只读与草稿区产出

小助理对 Vault SHALL 保持只读（沿用知识库既有只读承诺）。小助理的全部产出 SHALL 写入工作台自己的**草稿区**（独立于 Vault 的存储），SHALL NOT 直接写入、修改或删除 Vault 内任何文件。草稿区 SHALL 支持列表查看、内容预览与删除。

#### Scenario: 整理产出进草稿区

- **WHEN** 用户让小助理整理一篇文档或一段热点素材
- **THEN** 小助理产出一条结构化 Markdown 草稿，写入草稿区，Vault 内无任何文件变化

#### Scenario: 草稿区可管理

- **WHEN** 用户打开草稿区
- **THEN** 可看到全部草稿列表（标题、来源、生成时间），可预览内容、可删除草稿

#### Scenario: 只读边界不被突破

- **WHEN** 小助理执行任何整理任务
- **THEN** 系统不发生对 Vault 内文件的创建、修改、删除或移动

### Requirement: 三个整理能力

小助理 SHALL 提供三个整理能力，产出均进草稿区：① 提交文档 → 整理成结构化 Markdown（保留关键事实与来源）；② 提交每日热点素材 → 整理为灵感库方向的选题素材卡；③ 发起知识库体检 → 产出「整理建议」（如重复主题、缺失标签、可互链的孤立文档），以建议清单 + 预览形式呈现，SHALL NOT 自动改动任何已有文档。

#### Scenario: 文档整理成 md

- **WHEN** 用户选择一篇知识库文档并让小助理整理
- **THEN** 草稿区新增一条结构化 Markdown 草稿，内容基于该文档且标注来源路径

#### Scenario: 热点素材整理

- **WHEN** 用户从每日热点选一条素材让小助理整理
- **THEN** 草稿区新增一条选题素材卡草稿（含素材要点与来源）

#### Scenario: 知识库体检只出建议

- **WHEN** 用户发起知识库体检
- **THEN** 小助理产出整理建议清单（可预览），既有文档不被自动修改
