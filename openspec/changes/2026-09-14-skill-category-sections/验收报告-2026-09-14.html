一做了什么

1.1 背景：改造前的两个真实问题

  • 技能挂载是一锅粥。配置弹窗里技能只有一条扁平列表，既看不出「电商文案模板」服务电商业务、「小红书合规违禁词清单」服务小红书业务，技能一多更没法管理。其实数据结构里早就留了 category 字段，只是后端把它硬编码成「文案」、前端从未读取——口子留好了，线没接上。
  • 幽灵挂载静默失效。seed 给 4 个 Agent 预置了 7 项技能/文件挂载，技能目录里实际只有 2 个技能 + 2 个文件；读不到时后端 .catch(() => '') 把错误吞成空串，UI 却仍显示「已挂载」。用户以为给了 Agent 7 个技能，实际只有 4 个生效，且毫无提示。

1.2 核心决策：幽灵挂载「实体化」而非删除

经用户决策，7 项挂载全部落为真实文件：3 项（SEO 关键词 / 质检清单 / 电商视觉规范）从既有外部技能库（2026-09-12-xiaohongshu-skills，100+ 个 SKILL.md）的 keyword-analysis、content-review、cover-design 源材料提炼成 2–4KB 的项目格式精简技能；其余 4 项（知识库整理 / 素材结构化 / 品牌手册 / 品牌视觉规范）原创撰写。新文件名与存量数据库已挂的名字严格一致，因此存量库的技能挂载零迁移即生效。

二优化了什么

六项核心优化，每项都针对一个具体的失效模式：

🗂目录即分类

分类由技能文件所在子目录决定（ecommerce/xhs/common），文件头 > 分类： 可覆盖，未知值原样保留。加新技能退化为「把文件丢进对应目录」，零代码、零映射表维护。

🧭自构建索引，根除静默失效

改造前 readSkillContent 只会按根目录扁平路径找文件——文件一旦移入子目录，所有技能注入会静默变成空串（无报错无日志）。现在首次扫描即构建 id→绝对路径 懒加载索引，所有读取先查索引，索引未命中再回退扁平查找双保险。

⚡只读头部扫描

元数据约定在文件首部，解析标题/描述/分类只读文件头部若干 KB，不再为列个清单读整个技能全文。技能增多后目录扫描依然快。

🚨失效挂载可见

后端不再静默吞掉读空的技能，前端比对目录后把查不到的挂载项标红「已失效」并保留移除按钮。消除「UI 显示已挂载、实际注入为空」的静默退化。

🔄零迁移目录化

技能 id = 文件名保持不变，skillMounted() 同时匹配 id 与展示名——目录结构随便调整，历史挂载数据一条都不用改、继续生效。

🛡幂等存量迁移

存量库里指向白名单外 .pdf（永远读空）的文件挂载，由 ensure.ts 启动迁移精确替换为 .md 对应物；仅精确匹配两个文件名，JSON 解析失败的行跳过不动，二次执行零变化。

另外两项质量优化：① 跨目录同名技能 跳过并告警（而非静默取先命中者），让重名问题在启动日志里可发现；② 顺手修复主干既有的 asNote 判定回归（第五节），电商任务的卖点清单不再被错误渲染成小红书笔记格式。

四实现点 × 小白解释（重点）

下表把本次每个实现点翻译成「没有技术背景也能听懂」的大白话。最右列就是给非技术同学看的小白解释。

实现点 技术上做了什么 小白解释（人话版）
目录即分类 技能分类由所在子目录决定（ecommerce/xhs/common），文件头 > 分类： 可覆盖目录值，未知值原样保留 给技能文件分了三个抽屉：电商、小红书、通用。文件放进哪个抽屉就自动归哪类；特殊情况还可以在文件第一页写一行小字纠正。以后加新技能只要「把文件丢进抽屉」，一行代码都不用改。
自构建索引 listSkills 首次扫描时构建 id→绝对路径 懒加载索引并缓存，readSkillContent 所有读取先查索引，未命中再回退根目录扁平查找 程序第一次找技能时，会顺手画一张「哪个技能在哪个文件夹」的地图并存起来，之后每次取技能都按地图直达。再也不会因为「忘了先翻目录」而拿到一张白纸——这是本次最要命的老毛病（技能会悄悄失效且毫无报错），现在被根除了。
只读头部扫描 解析标题/描述/分类只读技能文件头部若干 KB，不再全文读取 想知道一本书叫什么名字，翻开头几行就够了，不必把整本读完。技能越加越多，列目录的速度也不受影响。
递归扫描 + 稳定排序 listSkills 遍历根目录与三个分类子目录，按「电商→小红书→通用」固定顺序输出 找技能时会翻遍所有子文件夹，再把结果按固定顺序摆整齐——界面上技能的位置稳定，不会今天在这明天在那。
同名技能告警 跨目录出现同名技能 id 时，保留先扫描到的、跳过后者并 console.warn 输出完整路径 两个抽屉里出现同名技能时，程序会大声喊「有重名！」，而不是偷偷随便挑一个装作没事——重名会让挂载指向错误的技能，喊出来才能第一时间修。
零迁移目录化 技能 id = 文件名保持不变，skillMounted() 同时匹配 id 与展示名，存量库不迁移 技能只是搬了家，没换身份证。数据库里登记的老名字全部还能对上号，一条数据都不用改、挂载全部继续生效。
幂等存量迁移 ensure.ts 启动时把存量库 agents.files 里的「品牌手册.pdf / 品牌视觉规范.pdf」精确替换为 .md 对应物，二次执行零变化 这就像补墙：补一遍是补好，补一百遍结果也一样，绝不会越补越歪。老数据库里那些「永远打不开的 PDF 挂载」在下次启动时自动换成能读的 Markdown 版。
分区挂载面板 AgentSettingsModal.tsx 技能区从扁平列表改为按分类分块渲染，分区标题右侧显示「已挂 N/M」计数 挂载面板从「一锅粥」变成超市货架：电商区、小红书区、通用区分开放，每区还标着「已挂 2/3」，一眼看清挂了几个、还剩几个没挂。
分类徽标 已挂载列表项显示来源分类徽标，取值来自目录比对 每个已挂技能上都贴着业务线小标签（电商/小红书/通用），不用再靠名字猜它是干嘛的。
失效挂载标记 前端拉取目录后比对，查不到的挂载项显示红色「已失效」并保留 × 移除按钮；后端不静默剔除 挂载的技能哪天被删了也不怕：界面会亮红灯告诉你「已失效」，还能一键拆掉——不再假装它还在干活。选择在界面上亮灯而不是后台悄悄隐藏，就是为了让问题看得见。
技能实体化 seed 预置但实际不存在的 7 项挂载全部落为真实文件：3 项从外部技能库源材料提炼、4 项原创撰写，均 2–4KB、注明来源 过去名单上写着的技能有 5 个是「空头支票」——文件根本不存在，Agent 读到的全是空白。现在真的把内容写出来了（3 个参考了外部技能库的现成材料，4 个新写的），Agent 终于能真正「学到」这些本事。
seed 挂载全集 seed.ts 修正为与实际文件严格一致：美美 3 技能+品牌手册、平平 电商视觉规范+品牌视觉规范、波波 质检清单、依依 知识库整理+素材结构化 新装系统时，四个 AI 助理一出生就自动带好各自的整套技能，不用再手工一个一个挂，也不会再出现「名单上有、实际没有」。
asNote 判定修复 交付物打包的笔记/文案判定改为 isXhsWorkflow(task.workflowId) && copySource.stage.startsWith('xhs-')，Note 分支改用 NotePackage 正确字段（body/tags） 顺手修好一个老毛病：给电商任务写的「核心卖点」清单，以前会被错误地当成小红书笔记来排版，卖点全丢；现在电商归电商格式、小红书归小红书格式，各走各的通道。
冷启动回归测试 skills.test.ts 专项：进程内不先调 listSkills 直接 readSkillContent 必须命中子目录技能；验收脚本 E1 再覆盖 seed 全集 9/9 专门出的一道考题：服务器刚重启、还没翻过目录时，直接伸手拿技能也必须拿得到——防止「重启后技能悄悄失踪」这种最难发现的 bug 被测出来、以后改坏了也立刻会被抓住。

五计划外修复（主干既有回归，非本 change 引入）

跑全量回归时发现 delivery/package.test.ts 的「文案+图片+manifest」用例失败。排查确认是主干既有缺陷（上一次提交 c046ecb 引入），恰好位于本次改造的技能注入交付链路上，已顺手修复：

  • 病因一：asNote 用 copyStages.includes(copySource.stage) 判断是否按小红书笔记渲染——电商任务的文案阶段也命中，导致电商 CopyPackage 被误走 Note 分支，points（核心卖点）字段被丢弃。
  • 病因二：Note 渲染分支误用 cp.outline / cp.keywords——那是 CopyPackage 的字段，NotePackage 实际字段是 body / tags。
  • 修复：判定改为 isXhsWorkflow(task.workflowId) && copySource.stage.startsWith('xhs-')（只有小红书工作流的 xhs-* 阶段才走笔记分支），Note 分支改用正确字段渲染正文与话题标签。
  • 结果：该文件 7/7 用例通过；本次验收脚本 A4 进一步确认电商任务产出 CopyPackage 结构完整（5 条卖点）。全量 281 组断言 0 失败。
