## Context

P1 承接 P0 归档后的基线。三处上下文决定了本变更的做法：

- **列宽**：P0 已把看板改为固定 300px + 横向滚动并同步进主 spec，但用户实测该方案与实际布局不兼容——「右侧空白一块、侧栏展开被挡住、拖分隔条不缩放、浏览器缩小不适配」。根因是固定宽度不响应容器变化，且容器的实际宽度取决于左右两栏（两者均可折叠/拖动）。本变更改为等宽自适应。
- **侧栏**：知识库页与星图页各自实现了目录树与折叠控件（`KnowledgeView.tsx` 与 `KnowledgeGraphView.tsx`），「收起目录」在两页位置不同，且知识库页的控件在页面右上角、距目录树约 1000px。
- **重点目录**：`packages/shared/src/knowledge.ts` 中 `status.presets` 的类型是 `{ type: 'dir'; products: string; brand: string }` —— 固定两项，后端读设置表回退内置常量 `KB_GRAPH_PRESETS`。要变成可增删改，需同时改类型、后端路由与两页的消费方式。

约束：颜色只用 `--color-*` 令牌；只用 `qs-*` 类与 `ui.tsx` 既有组件；不动效夸张化；**保持「只读接入，不修改 Vault 内任何文件」的承诺**。

## Goals / Non-Goals

**Goals:**

- 看板四列随容器自适应，等宽、不溢出、不留空
- 工位栏默认展开，折叠态可辨识（头像 + 名字 + 岗位）
- 卡片腾出高度（头像移右上角、删除重复状态行）
- 通知授权归入运行设置，顶栏收敛
- 知识库信息架构收口：总览带重构、公共侧栏、重点目录可维护、搜索候选、空态引导
- 任务详情去掉重复与机器字段

**Non-Goals:**

- 不实现 DocPreviewModal / 灵感库重构 / 知识库小助理功能（总览带只为小助理**预留入口位**）
- 不改动 Vault 真实文件夹（只做显示名映射）
- 不改动工作流状态机、WS 协议、Agent 执行链路
- 不引入新的第三方依赖

## Decisions

### 1. 看板列宽：等宽自适应 + `min-w-[240px]` 兜底

四列统一 `flex-1`，容器加 `min-w-0` 保证可收缩；每列 `min-w-[240px]`。容器已有 `overflow-x-auto`，当四列总宽低于 4×240px 时自然触发横向滚动。

**为什么是 240px**：卡片主按钮已独占一行、次要操作收进 `⋯`，折行风险显著低于 P0 之前；240px 足以容纳「确认开工」四字按钮与进度条（`white-space: nowrap` 已在 `.qs-btn` 中）。**替代方案**：纯 `flex-1` 无最小宽度 —— 否决，极窄视口下卡片会挤到不可读。

### 2. 公共 `KnowledgeSidebar`：抽取而非重写

新建 `features/knowledge/KnowledgeSidebar.tsx`，接受「目录树数据 + 标签数据 + 折叠状态 + 选择回调」；知识库页与星图页各自传入自己的过滤语义（知识库：目录筛选 + 标签筛选；星图：目录单选 + 标签多选 + 孤岛开关）。折叠控件放在组件内的标题栏，两页共用同一位置。

**风险点**：星图左树的交互（单选目录、多选标签、孤岛开关、已激活条件条）比知识库页复杂。抽取时把「容器 + 折叠 + 标题栏」共用，把「过滤控件」作为 children 传入，避免把两种交互硬塞进一个组件。

### 3. 重点目录：从固定两项升级为可增删改列表

```
packages/shared/src/knowledge.ts
  status.presets: { type:'dir'; products: string; brand: string }   ← 现状
                  ↓
  新增 KnowledgePresetEntry { id, label, dir } 与 status.presets: KnowledgePresetEntry[]
```

后端新增读写路由（沿用既有 settings 表持久化，不新建表）。**兼容**：读取到旧结构（`{products, brand}`）时映射为两条列表项，避免用户既有配置失效；读取为空时回退内置常量。

**替代方案**：不改类型、把用户自定义项存在前端 localStorage。否决——配置无法跨设备/跨会话一致，且与既有「预设依据存设置表」的做法不一致。

### 4. 工位栏默认展开 + 折叠态头像行

`expanded` 初值由 `false` 改为 `true`。折叠态改为：每个 Agent 一个小 `Avatar`（size ≈ 20）+ `qs-dot` 状态点 + 名字 + 岗位（`Badge` 或 `qs-meta`）。复用既有 `Avatar` / `Badge` / `agentColor` / `agentDotClass`，不新增组件。

**注意**：文档曾要求「工位栏本轮不改动」，该约束属于 P0；本轮用户明确要求改为默认展开并优化折叠态，故这条约束在本变更中不再适用。

### 5. 通知归位：顶栏删除控件，运行设置新增「通知」分区

把 `App.tsx` 的 `NotifyControl` 从顶栏移除，其逻辑（localStorage 开关 + 权限状态 + 被拒指引）移入 `LeftPanel` 的运行设置弹窗新增分区。顶栏只留「任务」入口（角标改为「N 待确认」）与连接状态点。

**风险点**：权限申请必须仍由**用户显式点击**触发（不能因打开设置弹窗就自动申请）。被拒后的指引文案已存在（`App.tsx` 内已有地址栏指引），整体搬移而非重写。

### 6. 审批条：承载操作而非只做说明

审批条现为「标题 + 一句 55 字说明」。改为：标题 + **采纳 / 打回按钮** + 一行短说明（如「待你确认 · 采纳后自动进入主图设计」）。按钮逻辑复用卡片内既有实现，需保证两个位置的决策行为一致且不重复推进阶段（打回仍需填写原因）。

**风险点**：同一决策出现两个入口可能造成重复点击。做法是审批条按钮与卡片内按钮共用同一 `busy` 状态与同一决策函数，禁用状态同步。

### 7. 机器字段退出正文（**涉及后端**）

`backend/src/knowledge/refs.ts:399` 目前把 `原文：${url}` 等字符串拼进任务描述正文。改为：溯源信息作为**结构化字段**随任务返回，前端在属性面板「来源」区块渲染，原文做成可点击的外链。描述正文只留内容本身。

**这是本变更唯一的后端数据整形改动**，需同步 `packages/shared` 的任务类型。若既有任务的描述里已含旧拼接文本，采用**读取时清洗**而非批量改库，避免破坏历史数据。

### 8. 目录中文显示名映射（不改 Vault）

新增「真实目录路径 → 中文显示名」映射（`packages/shared` 声明类型，后端读取设置表，提供内置默认如 `10_raw/products → 产品资料`）。目录树渲染中文名，悬停与设置中展示真实路径。**绝不对 Vault 做重命名**，否则会使既有 wiki 链接失效。

### 9. 小助理入口复用「工位 Agent 卡」组件（用户定案）

总览带的「小助理」入口位**就是工位里那张 Agent 卡**——复用 `WorkstationBar` 渲染 Agent 卡的那段结构（头像 + 状态点 + 名字 + 角色 Badge + 模型/活动行 + 配置按钮），不另造一种入口形态。

据此把该段卡片结构从 `WorkstationBar` 中**抽为可复用组件**（如 `features/workstation/AgentCard.tsx`），供两处共用：工位栏（遍历 `agents` 渲染多张卡）与总览带（渲染小助理这一张卡）。抽取后工位栏既有的展开态渲染、`配置` 按钮打开 `AgentSettingsModal`、状态点/颜色的 `agentStatus` 语义 SHALL 保持不变。

**P2 的落地路径**：P2 只需新增一个 `type: 'assistant'` 的 Agent 实例（`packages/shared` 的 `AgentRole` 增加角色、`backend/src/db/seed.ts` 增加一条 seed），该卡即自动在工位与总览带出现，无需再改这两处 UI——这正是用户要的「后续 P2 可以快速增加」。

**本轮边界**：本轮**不**创建 assistant Agent 实例、**不**扩 `AgentRole` 联合类型、**不**改 seed。总览带的小助理位在功能落地前按「占位但不死链」处理。

## Risks / Trade-offs

- **公共侧栏抽取可能破坏星图左树的既有交互** → 采用「容器共用 + 过滤控件作为 children」的边界，抽取后逐项回归星图的目录单选、标签多选、孤岛开关与已激活条件条。
- **重点目录类型变更影响两页与后端** → 保留旧结构的读取兼容映射；后端读不到新结构时回退内置默认，保证升级后界面不空白。
- **审批条与卡片双入口导致重复决策** → 共用 `busy` 与决策函数，点击后两处同时禁用。
- **通知移入设置后权限链路被破坏** → 保持「仅显式点击申请」语义；搬移后手工验证申请、拒绝指引、已授权三种状态。
- **等宽自适应后极窄视口需横向滚动** → 这是刻意的取舍（`min-w-[240px]`）；验收需覆盖 1440 / 1024 / 窄窗三档。
- **机器字段退出正文涉及后端与既有数据** → 采用读取时清洗，不改库；验收需覆盖已有任务与新任务两种情况。
- **Agent 卡抽取后工位栏可能回归** → 抽取只移动结构不改行为；验收需覆盖工位栏展开态的 `配置` 按钮、状态点颜色与折叠态图标行。
- **小助理入口位在功能未实现时可能是死链** → 占位卡复用既有组件呈现，明确在 spec 中要求「不呈现为不可用的死链」。
