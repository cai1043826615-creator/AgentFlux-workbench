## Context

本轮 6 项 P0 全部落在前端，无后端与共享契约改动。三处实现现状直接决定了各自的可行性：

- **星图**：`KnowledgeGraphView.tsx` 已有完整的 `fitView()`（L345-365），它按可见节点包围盒计算 zoom 与 pan。但该函数依赖 `sizeRef.current`（画布实测宽高），而画布尺寸在首次渲染后才可知——这决定了调用时机不能简单地放在数据加载的 `.then()` 里。
- **看板**：`BoardView.tsx` L291 的类名按列是否有卡片二选一（`w-[96px] flex-none` vs `min-w-[200px] flex-1`），即列宽由「数据」驱动而非由「设计」驱动，这是失衡的根源。
- **热点**：`HotView.tsx` L725-739 用 `if (tier === 'other' && collapsedOther)` 提前 return 一个按钮来渲染折叠态，展开态走 `return <section>` 分支且该分支内没有任何回收控件——即折叠是单向的。

约束（来自 `docs/测试文件/UI组件沉淀与设计规范.md` 与本轮决策）：颜色只能用 `--color-*` 令牌；只能用 `qs-*` 类与 `ui.tsx` 既有组件；动效需支持 `prefers-reduced-motion`；`--color-signal` 保持 `#7C3AED` 不变（用户定案）。

## Goals / Non-Goals

**Goals:**

- 消除 6 项 P0 缺陷，使既有 spec 描述的行为与实现一致
- 修正「空列压缩」这条本身失衡的既有要求（它当前写在 `task-board` 主 spec 里）
- 把 Markdown 链接色问题从「漏修一处」升级为「结构性约束」

**Non-Goals:**

- 不调整 `--color-signal` 的色值，不改动任何既有 `--color-*` 令牌
- 不做 P1 的信息架构调整（总览带重构、公共侧栏抽取、重点目录、通知移入设置、小助理预留位）
- 不实现 P2 的 DocPreviewModal / 灵感库重构 / 小助理功能
- 不改动工位栏（位置、结构、折叠行为均不变）
- 不引入任何新的第三方依赖

## Decisions

### 1. 星图 fitView：用「已上屏 + 尺寸就绪」双条件触发，而非在数据加载回调里直接调用

数据加载完成的时刻，画布元素可能尚未完成布局（`sizeRef.current` 仍为初始值），此时 `fitView()` 算出的 zoom/pan 会基于错误的画布尺寸。做法：在既有的 `useEffect` 依赖链之外，新增一个 effect 监听「图谱数据已就绪」与画布尺寸就绪，用一个 ref 标记保证**只自动适配一次**；此后用户的手动缩放/拖拽不再被覆盖（对应 spec 的「手动视图不被自动适配覆盖」场景）。

**替代方案**：在 `load()` 的 `.then()` 里 `setTimeout(fitView, 0)`。否决——依赖时序竞争，且窗口 resize 或过滤变化时语义不清。

### 2. 看板列宽：固定 300px + 容器横向滚动，空列不特殊处理

四列统一 `w-[300px] flex-none`，容器保持既有 `overflow-x-auto`（L287）。删除「有卡片/无卡片」的条件类名分支，列宽不再由数据决定。

**取消「空列压缩」要求的原因**：该要求导致 96/96/456/456 的极端失衡，且压缩腾出的宽度会让满列卡片变宽而重新触发按钮折行——即上轮刚修复的缺陷会复发。Trello/Jira/Linear 的通行做法是固定列宽 + 横向滚动。

**替代方案**：四列等分（`flex-1`）。否决——1440px 下每列约 300px 是临界值，窄视口等分后必然小于 300px，按钮折行回归。

### 3. 「其他」分组：把折叠改成双向状态，并在展开态保留切换控件

不再用「提前 return 一个按钮」表达折叠态，改为统一的 `section` 结构：标题行始终渲染，标题行右侧根据 `collapsedOther` 渲染「展开 ▾ / 收起 ▴」控件，卡片列表按 `collapsedOther` 条件渲染。这样展开态也必然存在回收控件。

同时把分组标题行拆开：标题行只显示「其他 · 12 条」，判定口径（「未命中关注域」）移入 `title` 属性。

### 4. 历史版本：当前正文置顶 + 历史收为标题栏控件、默认收起

调整 `ContentDeliveryView.tsx` 的渲染次序——当前正文在前，历史版本的可折叠面板在后。折叠状态用组件内 `useState`（默认 `false` = 收起）。复用既有的「与上一版对比」面板内容，不重写对比逻辑。

### 5. 参考图文案：把判定从「有/无 AI 主图回退」改为「有/无用户上传参考图」

现有代码（L213）的注释表明回退逻辑是「无用户上传参考图时回退显示 AI 生成主图」，但顶部文案没有随之分叉。做法：在文案处复用同一个判定条件（用户是否上传了参考图），二分输出文案。

### 6. Markdown 链接色：补「工具类不得覆盖令牌」的约束，不改色值

现状：`Markdown.tsx` L37/L53 已用行内 `style={{ color: 'var(--color-signal)' }}`，而 `--color-signal` 的值恰好是 `#7C3AED`（与 Tailwind violet-600 同值）。因此「计算色是 violet-600」是**值巧合，不是类名覆盖**——全库检索 `violet|purple|indigo` 类名命中 0 处。

据此，本轮不追查不存在的类名覆盖，而是补一条**结构性约束**：在 `index.css` 中确保文档正文链接色以令牌为唯一来源，并在 `@layer components` 中给链接色规则足够的优先级，使将来任何工具类都不易覆盖它（沿用项目既有做法：组件类必须置于 `@layer components`，见 index.css L59-61 的既有注释）。

**替代方案**：改 `--color-signal` 的值。否决——用户已定案保持 `#7C3AED`，且改令牌会全站变色，属品牌层变更。

## Risks / Trade-offs

- **fitView 触发时机仍可能撞上尺寸未就绪** → 以「尺寸就绪」为前置条件之一，并加 ref 保证只执行一次；若首次仍偏差，可在容器 `ResizeObserver` 首次回调后再适配一次，但需保证不会覆盖用户手动视图。
- **看板固定 300px 后，窄视口必须横向滚动才能看到全部四列** → 这是刻意的取舍（换取卡片宽度恒定与按钮不折行）；需在验收时确认横向滚动可用且不遮挡工位栏。
- **`ContentDeliveryView` 区块次序调整可能影响采纳/打回按钮的可达性** → 保持按钮仍在卡片内原位置，只移动「历史版本」区块；验收需覆盖待确认态的采纳/打回流程。
- **`task-board` 主 spec 中「Empty column compressed」被改写为新语义** → 该场景名保留（避免归档时丢失），仅将其 THEN 反转为「不压缩」；归档后主 spec 描述与实现一致。
- **热点标题行去掉判定口径文字后，用户可能不知「其他」的含义** → 移入 `title` 提示，鼠标悬停可见；属可接受的降噪取舍。
