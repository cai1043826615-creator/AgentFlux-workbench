## Context

热点模块现状（daily-hot 主 spec）：4 个源（电商派/网经社/统计局/AI行业聚合）、按信源数分层（必看/浏览/其他）、卡片操作「挂为任务背景」。用户在真实使用后判定：这些资讯对电商上架产出「一点用没有」，并点破核心认知——**「我要是知道现在趋势是什么就好了，就是不知道才要从热点去抓」**。这句话否定了「预设趋势词表」的路线，确立了「榜单标题本身是趋势信号，交给 AI 判断产出价值」的路线。

已有的关键基建：小助理执行链（`assistant.ts`，LLM 调用+执行日志）、收件箱（`kb_drafts` 表 + 已并入知识库「助理收件箱」虚拟目录）、适配器注册表（`hot-sources/index.ts`，可插拔、单源降级）。本变更全部建立在这些之上，不需要新架构。

用户已确认的取舍：① AI 打标成本可接受（每批一次调用，几分钱级）；② 分层改为「产出方向/可参考/无关」；③ 热点不再挂任务（收进灵感替代）；④ 热榜类源抓全量不做入站关键词过滤。

## Goals / Non-Goals

**Goals:**

- 热榜源扩充：百度热搜 + 微博/抖音热榜（60s API）+ 头条热榜，删统计局源
- AI 产出价值打标：批量一次调用、随热点缓存复用、失败降级不阻塞
- 展示重构：产出方向 / 可参考 / 无关（默认折叠）三分组，卡片带方向标签与用法建议
- 「收进灵感」：热点→依依→灵感方向卡→助理收件箱，替代「挂为任务背景」
- 统计口径：今日收集 N 条 · 产出方向 N · 可参考 N · 条目最新发布日期（区分抓取新旧与上游停更）

**Non-Goals:**

- 不做关键词订阅/趋势词表维护
- 不做热点历史存档、趋势曲线
- 不改工作流状态机与任务派发
- 不删除既有 task_hot_refs 数据（只读保留）
- 不做星图性能优化（另列）

## Decisions

### 1. 打标挂在聚合层，结果内嵌条目（而非独立表）

打标发生在 `loadHotPanel` 拉取并去重之后：把全量标题一次发给 LLM，返回 JSON 数组（每条 `{t: 序号, c: class, tag: 方向标签, use: 用法建议}`），按序号合并回条目。结果随 HotPanel 一起写入热点缓存（同一 15 分钟 TTL）——**不建新表**。

**替代方案**：打标结果独立表+按热点 id 持久化。否决——热点条目本身是易逝的（榜单滚动），id 稳定性差；跟随缓存同生命周期语义最简，且缓存已有版本指纹机制。

### 2. 打标提示词：判断标准写死在 prompt，输出强制 JSON

system 规定三类的判断标准：**产出方向**=能直接变成主图/详情页/选品/内容选题（如配色趋势、爆品元素、平台玩法）；**可参考**=行业背景但无直接产出指向；**无关**=纯社会娱乐新闻。要求输出 `{"items":[{"t":1,"c":"dir|ref|none","tag":"🎨 视觉趋势","use":"可用于主图配色"}]}`，`t` 是输入序号。解析失败→整批降级为可参考。

**替代方案**：逐条调用打标。否决——60-90 次调用的成本与延迟不可接受。

### 3. 榜单类源的 latestAt 语义 = 抓取时刻

微博/抖音/头条/百度热榜是「此刻热度」语义，无发布时间。统一取抓取时刻作 latestAt，这样信息条的「条目最新发布」对榜单源等于「最近一次在榜确认」。电商资讯源（电商派/网经社）保持真实发布时间。**这个混合语义在信息条 title 里说明**，避免用户混淆。

### 4. 分组渲染复用既有「其他分组」折叠机制

「无关」分组直接复用 P0-3 做的标题行双向折叠（`data-collapsed` + ▸/▾），「产出方向」「可参考」始终展开。卡片上加方向徽章（🎨📦✍️🛒 按类别）与一行用法建议。

### 5. 「收进灵感」走既有 assistant 通道

新增 `AssistantKind 'inspire'`：输入热点条目（id/title/summary/sourceName/url），提示词产出「灵感方向卡」（趋势要点/产出方向/适配品类场景/来源），写 `kb_drafts`。前端按钮直接 POST，成功后 toast 指向知识库「助理收件箱」目录。**删除**：热点卡片「挂为任务背景」按钮、任务详情「关联热点背景」入口（既有数据只读保留）。

**替代方案**：前端直接把热点摘要写入 kb_drafts（不过 LLM）。否决——收进灵感的价值恰恰是依依的加工（趋势要点+产出方向），裸存摘要没有增量。

### 6. 关注域配置弹窗降级为「源管理」

AI 打标取代了关键词分层的职责，原「关注域配置」（关键词/排除词/多词阈值）失去主作用。弹窗保留**数据源管理**（启用/禁用/端点），关键词编辑区隐藏但数据不删（回滚保险）。降噪逻辑（排除词/阈值）在代码中**短路为恒通过**——不是删除，是旁路。

## Risks / Trade-offs

- **AI 打标错分类** → 提示词给出明确正反例；「无关」默认折叠所以错杀可见性低；用户发现错标可「收进灵感」人工兜底
- **LLM 延迟叠加拉取延迟** → 打标在拉取后异步执行+面板先渲染未打标状态（条目进「可参考」，打标完成后下一次轮询刷新分组）——不做阻塞式等待
- **热榜接口变动/反爬** → 适配器抛错即单源降级（既有机制），4 个热榜源同时全挂的概率低
- **旧「挂任务」用户找不到入口** → 收进灵感 + 收件箱承接；历史任务数据只读保留不丢失
- **关注域配置弹窗简化可能被误解为丢配置** → 隐藏不删除，回滚仅需去掉旁路
