## Why

热点模块现在的定位是「行业资讯播报」——抓平台新闻/监管动态/竞品融资，按信源数分层。但用户在实际使用中明确指出：**这些内容对电商上架产出一点用没有**。真正需要的是「现在流行什么、能变成什么产出」——比如「多巴胺配色」上榜，就该直接变成主图配色/详情页风格的方向参考。同时用户点破了关键认知：**我们不知道趋势是什么才要抓热点**——所以不能靠预设关键词过滤（鸡生蛋），而要让 AI 从榜单标题里识别「什么正在流行、能怎么用」。此外热点与任务的关系需按既有边界（「热点不派生任务」）再进一步：热点是知识库的灵感上游，不是任务输入，删除「挂为任务背景」。

## What Changes

**定位重定义**：热点模块从「行业资讯播报」转为「**产出灵感雷达**」——回答的不是「行业发生了什么」，而是「**现在流行什么、我能怎么用**」。

**① 源层扩充（抓全量候选）**

- 新增 3 个热榜适配器：百度热搜、微博/抖音热榜（60s API）、今日头条热榜（均为调研文档已验证 P1 源、无需 key）。
- 删除 `stats-sjjd`（国家统计局——纯宏观数据，零产出价值）。
- 抓取策略改为**广撒网**：热榜标题本身就是趋势信号，不做入站关键词过滤（预过滤与「不知道趋势」的前提矛盾）。

**② 识别层（AI 批量打标，本变更核心）**

- 每批热点拉回后，由小助理（LLM，deepseek-chat）**批量打标**：对每条标题判断「能否变成电商产出 + 属于什么方向 + 怎么用」。
- 打标输出四类：`产出方向`（可直接变主图/详情页/选品方向，如「多巴胺配色→主图配色方案」）、`可参考`（有背景价值）、`无关`（默认折叠）。
- 打标结果缓存到条目（随热点缓存 TTL 一致，15 分钟），不重复调用。
- LLM 失败降级：全部标为「可参考」并注明「AI 识别暂不可用」，不阻塞面板。

**③ 展示层（新分层）**

- 分组从「必看/浏览/其他」（信源数逻辑）改为「**产出方向 / 可参考 / 无关（默认折叠）**」。
- 「必看/浏览/其他」与「多源共振」等资讯概念退出界面。
- 统计区讲清口径：今日收集 N 条 · 产出方向 N · 可参考 N · 更新时间。
- 热点卡片显示 AI 判断的方向与用法建议（如「🎨 视觉趋势 · 可用于主图配色」）。

**④ 沉淀层（收进灵感，替换挂任务）**

- 卡片操作「挂为任务背景」→ 改为「**收进灵感**」：调小助理把该热点整理成「灵感方向卡」写入**助理收件箱**（复用既有 kb_drafts 通道与「助理收件箱」虚拟目录）。
- 删除任务详情「任务背景 · 外部环境情报」面板的**新增入口**（既有已挂数据保留只读展示，避免破坏历史任务）。
- 热点卡片「原文 ↗」保留。

**非目标**：

- 不做关键词订阅/自定义趋势词表（AI 识别取代它）。
- 不改热点与任务的既有边界（仍不派生任务、不自动创建任务）。
- 不做热点历史存档/趋势曲线（后续可议）。
- 星图性能优化（另列）。

## Capabilities

### New Capabilities

- `hot-trend-radar`: 产出灵感雷达能力——热榜广撒网抓取、AI 产出价值打标、三分组展示、收进灵感沉淀通道。

### Modified Capabilities

- `daily-hot`: 面板定位从资讯播报改为产出灵感雷达；分组模型替换；统计口径替换；卡片操作替换（挂任务→收进灵感）。
- `hot-context`: 热点不再作为任务背景注入的新增来源（既有数据只读保留）；「手动挂热点为任务背景」能力废弃。
- `kb-assistant`: 小助理新增「热点打标」与「热点→灵感方向卡」两个职责。

| 新增 `knowledge/hot-tagging.ts` | AI 批量打标（输入标题列表 → 输出方向/用法建议；缓存随热点 TTL） |
| `knowledge/hot.ts` | 聚合层接入打标；分组模型替换 |
| `knowledge/assistant.ts` | 新增热点→灵感方向卡的整理类型 |
| `routes/knowledge.ts` | 「收进灵感」路由 |

**前端**

| 文件 | 改动 |
| --- | --- |
| `HotView.tsx` | 三分组渲染、卡片操作改「收进灵感」、统计口径 |
