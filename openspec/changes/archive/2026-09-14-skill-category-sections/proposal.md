## Why

Agent 设置弹窗的挂载面板目前是一条**扁平技能列表**（`AgentSettingsModal.tsx` 的 `catalog.map(...)`），只列技能名与描述。但技能本身分成性质完全不同的两类：一条服务**电商**业务（`电商文案模板`），一条服务**小红书**业务（`小红书合规违禁词清单`）。挂载时用户看不出「这个技能属于哪条业务线」，只能靠技能名猜；技能变多后更会变成一锅粥。

更麻烦的是**失效挂载完全不可见**：seed 给 4 个 Agent 预置了 7 个技能/文件，实际目录里只有 2 个技能 + 2 个文件，读不到就静默返回空串（`skills.ts` 的 `.catch(() => '')`），而 UI 仍渲染成已挂载的 SKILL 标签。用户以为给了 Agent 5 个技能，实际只有 2 个生效。

现在做，是因为**分类字段早就存在但被写死了**：`AgentSkillInfo.category` 已在 `packages/shared/src/types.ts` 定义，`skills.ts:25` 却把它硬编码成 `'文案'`，前端也从未读取它。数据结构的口子已经留好，改动只是「把线接上」；拖得越久，越多技能会在没有分类的情况下堆进目录，后续迁移越贵。

## What Changes

- **技能目录改为「目录即分类」**：`backend/skills/<分类>/*.md`，新增 `ecommerce/`、`xhs/`、`common/` 三个分类目录，现有两个技能文件按业务线移入对应目录（**文件名保持不变**，仅移动位置）
- **`parseSkillMeta` 不再硬编码分类**：分类由所在目录决定，并支持技能文件头部 `> 分类：xxx` 覆盖目录值；未知分类保留原值而非丢弃
- **`listSkills` 递归扫描分类子目录**：根目录平铺的 `.md` 归入「通用」以兼容既有结构；跨目录同名技能 id 冲突时跳过并告警（避免已挂载数据匹配到错误技能）
- **挂载面板按业务域分区渲染**：技能区从扁平列表改为「电商 / 小红书 / 通用」分区块，每个分区标题右侧显示该区「已挂 N/M」计数
- **已挂载列表暴露失效项**：每项显示分类徽标；目录里查不到的挂载项标红「已失效」，不再假装生效
- **分区的分类维度定义**：「电商」是业务域、「小红书」是渠道，两者**不正交**，因此保留「通用」区作为兜底——新技能未标注分类时落入通用区，而非消失
- **修复幽灵技能挂载：实体化而非删除**。seed 预置的 7 项挂载全部落为真实文件：优先从既有外部技能库（`2026-09-12-xiaohongshu-skills/skills`，100+ 个 SKILL.md）中核对——无同名项，但有 3 项存在可提炼的源材料（关键词分析 → `SEO 关键词`、内容审核 → `质检清单`、封面设计 → `电商视觉规范` 的素材之一），按项目技能格式提炼成精简技能；其余 5 项（`知识库整理`、`素材结构化`、`品牌手册`、`品牌视觉规范` 及视觉规范剩余部分）由本轮撰写补齐
- **打通技能库 → Agent**：全部 seed 挂载项在目录中可解析、可注入；已存在的 `.pdf` 文件挂载（白名单外、永远读空）通过幂等迁移替换为 `.md` 对应物，存量数据库同样打通

### 非目标（本轮明确不做）

- **不改技能注入逻辑**：工作流专属技能的按 `workflowId` 过滤**已在上一轮实现**（`smart-producer.ts` 的 `WORKFLOW_SKILLS`），本轮不重复建设
- 不整库导入外部技能库：100+ 个 SKILL.md 体积大（4–44KB）、格式为英文 frontmatter，不直接拷贝进技能目录；本轮只按 seed 挂载需求提炼 5 个技能 + 撰写 2 个品牌文件，其余留待后续按需增补
- 不重命名既有 2 个技能文件（仅移动目录位置）；新撰写的技能文件名与 seed 挂载名**严格一致**，使存量数据库的挂载立即生效
- 不改技能内容的语义与文本（既有 2 个技能内容不动，仅头部补分类声明）
- 不引入「一个技能同属多个分区」的模型（保持 `category: string` 单值，避免本轮扩大改动面）
- 不改文件（FILES）区的结构与上传逻辑
- 不改 Agent 卡片、工位栏布局
- 不做技能内容的在线编辑

## Capabilities

### New Capabilities

（无：本轮不引入新的能力域，改动集中在既有工位的技能挂载语义上）

### Modified Capabilities

- `workstation`: 技能挂载从「扁平列表 + 分类恒为文案」改为「按业务域分区的技能目录 + 分类可解析 + 失效挂载可见」

## Impact

**共享契约层（`packages/shared`）**
- `types.ts`：`AgentSkillInfo.category` 由可选改为**必填**（字段本身已存在，仅收紧类型）

**后端（`backend/src`）**
- `agents/skills.ts`：`parseSkillMeta` 接收目录分类并结合文件头 `> 分类：` 覆盖；`listSkills` 改为递归扫描分类子目录、按分类排序、跨目录同名告警；新增分类顺序/中文名常量与排序权重函数
- `agents/smart-producer.ts`：**无需改动**（`readSkillContent` 的 id 语义不变；工作流专属技能过滤已存在）
- `db/seed.ts`：修正预置挂载，使其与 `backend/skills/`、`backend/files/` 实际内容一致

**技能目录（`backend/skills`）**
- 新增 `ecommerce/`、`xhs/`、`common/` 子目录
- `电商文案模板.md` → `ecommerce/`；`小红书合规违禁词清单.md` → `xhs/`
- 新增 5 个技能文件（名与 seed 挂载严格一致）：`ecommerce/SEO 关键词.md`、`ecommerce/电商视觉规范.md`、`common/质检清单.md`、`common/知识库整理.md`、`common/素材结构化.md`（前三个自外部技能库源材料提炼，后两个原创；均标注来源）

**挂载文件目录（`backend/files`）**
- 新增 `品牌手册.md`、`品牌视觉规范.md`（原创，替代 seed 里白名单外、永远读空的 `.pdf` 挂载）

**数据库迁移（`backend/src/db/ensure.ts`）**
- 新增幂等迁移：`agents.files` JSON 中 `品牌手册.pdf` → `品牌手册.md`、`品牌视觉规范.pdf` → `品牌视觉规范.md`，使**存量库**的文件挂载同样可解析

**前端（`frontend/src`）**
- `features/workstation/AgentSettingsModal.tsx`：挂载面板技能区改为分区渲染（分区标题 + 计数）、已挂载列表加分类徽标与「已失效」标记

**兼容性与数据迁移**
- `agents.skills` 列存的是技能**展示名**而非路径，且 `skillMounted()` 同时匹配 `id` 与 `name`：既有 2 个技能移动位置不影响挂载；新实体化的 5 个技能**文件名与存量库已挂的名字严格一致**，存量库的技能挂载因此**无需迁移即生效**
- `agents.files` 中存量库的 `品牌手册.pdf` / `品牌视觉规范.pdf` 指向白名单外文件（必然读空），由 ensure.ts 幂等迁移替换为 `.md` 对应物

**验收影响**
- 技能注入行为必须回归零差异：同一 Agent 在分类改造前后的最终 system prompt 应逐字一致（除分类元数据不参与注入外）
