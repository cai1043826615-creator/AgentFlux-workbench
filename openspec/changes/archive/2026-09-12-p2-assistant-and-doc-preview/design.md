## Context

P1 已归档，为 P2 铺好的路：总览带小助理位已预留（`useFirstAssistantAgent()` + `AgentCard` 组件）、公共侧栏与知识库设置弹窗已组件化、`Markdown.tsx` 的链接跳转已收敛为 `onOpenDoc` 单一出口。本轮两件事（F3 小助理 / F1 预览弹窗）都是在这些接缝上接线，不需要新的架构面。

两处关键现状决定了实现方式：

- **工作流与 agents 表天然解耦**：后端 `engine/executor.ts` 的 `AGENT_BY_ROLE` 与前端 `TaskDetailView` 的 `ROLE_TO_AGENT_NAME` 都是**硬编码三角色**（文案/设计师/主管），不查 role 字段。这使「小助理不参与工作流」天然成立——加角色不用改工作流代码，但**必须加防回归断言**（防将来有人把角色映射改成遍历式）。
- **前端 agents 消费者是全量遍历**：工位栏、聊天私聊行、状态页都是 `agents.map(...)`，加了第四个 Agent 后**自动出现**。用户定案是：工位栏不出现、聊天出现、状态页出现——所以工位栏需要显式过滤，其余两处不动。

用户 4 条定案（本轮的设计约束）：①涉及 Agent 的界面都要更新；②电商工作流不体现小助理；③总览带小助理位放**右侧**；④带与工位一致的**收起功能**。

## Goals / Non-Goals

**Goals:**

- 小助理成为真实 Agent：可配置、可私聊、状态页可见、总览带真实卡片
- 三个整理能力跑通（文档整理 / 热点素材卡 / 知识库体检建议），产出全部进草稿区
- 文档预览弹窗替代「跳页看文档」，保住星图与任务详情的上下文
- 工作流零感知：派发、阶段条、播报、群聊署名完全不变

**Non-Goals:**

- 不做 F2 灵感库重构（相关性分层 / 收进灵感库 / 灵感库设置，单独一轮）
- 不做小助理**写入 Vault**（沉淀落盘需用户另授权，本轮止步草稿区）
- 不做草稿的自动定时整理（「定期整理」本轮实现为**手动触发**体检，不做后台定时任务）
- 不改动工作流状态机、任务派发、WS 协议

## Decisions

### 1. AgentRole 加 `'助理'`：加值不加约束，隔离靠「白名单」而非「过滤」

`AgentRole` 联合类型加 `'助理'`。工作流侧的隔离**不依赖前端过滤**——后端 `AGENT_BY_ROLE` 与前端 `ROLE_TO_AGENT_NAME` 本来就是三角色白名单，小助理天然进不去；前端只做一处显式隔离：**工位栏**按「工作流三角色」渲染（`['文案','设计师','主管'].includes(role)`），因为它是纯展示遍历。

**替代方案**：给 Agent 加 `inWorkflow: boolean` 字段做通用开关。否决——过度设计，现有三处硬编码白名单本来就是隔离机制，加字段反而制造两份真相。

### 2. 草稿区 = SQLite 独立表 `kb_drafts`，不复用 deliverables

新建 `kb_drafts` 表（id / title / source_kind / source_ref / content / created_at），独立于任务交付物（deliverables 挂在 task 上，草稿挂在知识库侧）。只读承诺不破：草稿表在工作台库内，与 Vault 无关。「沉淀进知识库」本轮**不做落盘**，草稿详情页提供「在知识库中打开来源」与复制全文，落盘列为后续增强。

**替代方案**：草稿写成 Vault 里一个 `30_drafts/` 目录。否决——直接违反只读承诺，且你已定案产出进草稿区。

### 3. 小助理执行 = 复用既有 Agent 执行基建（llm.ts + executions 表），走聊天会话而非任务

小助理的「整理」请求通过**私聊消息**发起（在与其私聊中发指令，或总览带卡片上的快捷动作），后端走与既有 Agent 相同的 llm.ts 调用链，执行记录写既有 `agent_executions` 表（agent_id = assistant）——这样 Agent 状态页的统计自动工作，零额外统计代码。产出解析后写入 `kb_drafts`。

**替代方案**：给小助理建任务型执行流（像工作流一样有阶段）。否决——用户定案它不参与工作流，任务化反而把隔离打破。

### 4. DocPreviewModal 用 store 全局态而非路由

`docPreviewPath: string | null` 放 `useWorkbench`（与 `kbDocPath` 并列，不替换）。理由：弹窗是「当前页面的叠加层」，不产生路由变化——Esc/遮罩关闭后精确回到触发前状态；若用路由参数表达弹窗，前进/后退语义会变复杂。

**替代方案**：`#/doc/<path>` 路由化。否决——浏览器后退会变成「关弹窗」，与「后退 = 离开页面」的用户预期冲突。

### 5. Markdown.tsx 的 onOpenDoc 分场景注入，不改组件签名

`Markdown` 组件保持「接受 `onOpenDoc` 回调」的既有设计，行为分叉放在**调用方**：知识库页阅读区传「原地打开」，DocPreviewModal 内传「弹窗内切换」，星图/任务详情传「打开弹窗」。组件零改动，三处调用方各自语义清晰。

### 6. 总览带小助理位：位置移右 + 收起态一行

顺序调整为「核心指标 → 灵感库 → 全部文档 → 小助理（最右）」。收起态与工位栏折叠态同语义：一行紧凑条（小头像 + 名字 + 「展开」钮），展开后为完整 Agent 卡。状态存组件 state（会话内记忆，不落 localStorage——与工位栏行为一致）。

## Risks / Trade-offs

- **「按角色遍历」的前端可能漏改** → 工位栏显式三角色白名单；验收用 Chrome DevTools 断言工位栏恰好 3 张卡。
- **`'助理'` 加值可能让既有比较逻辑意外命中** → 全库检索 `role ===` 与 `role:` 排查；`ROLE_TO_AGENT_NAME` / `AGENT_BY_ROLE` 保持硬编码不动。
- **弹窗内 Markdown 链接与「弹窗内切换」形成递归栈** → 浏览栈设上限（如 20 层），超出后最早记录出栈；「返回上一份」在栈空时禁用。
- **小助理 LLM 输出格式不稳定导致草稿解析失败** → 解析失败时把原始输出整篇存为草稿（带「未结构化」标记），不丢内容、不报错中断。
- **`kb_drafts` 与知识库索引的一致性** → 草稿不进知识库索引（不属于 Vault），搜索与星图都不含草稿；spec 已写明。
- **两个 capability 同时动 `KnowledgeView`/`KnowledgeGraphView`** → 预览弹窗改动只换 `onOpenDoc` 注入，不碰侧栏/设置结构；按 F3 → F1 顺序串行实现，降低同文件冲突。
