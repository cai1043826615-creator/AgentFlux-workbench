# AgentFlux｜多 Agent 电商内容工作台

一个面向电商上新与小红书内容生产的多 Agent 协作工作台。它把任务资料、角色分工、阶段产出、人工审核、返工和交付归档放进同一条可追踪的工作流。

本仓库包含完整前端、后端、共享类型与工作流实现，并附带可选的浏览器沙盒演示模式。

## 给 HR：项目介绍

### 30 秒介绍

我围绕电商团队的内容生产流程，设计并实现了一套多 Agent 工作台。用户创建任务后，文案、设计和审核角色按业务阶段协作；系统在关键节点等待人工确认，支持打回返工、过程追踪和最终交付。项目覆盖电商新品上架与小红书种草两类内容工作流。

### 我负责的工作

- 梳理内容团队从需求收集到素材交付的业务链路，定义阶段、角色和人工审核边界。
- 设计任务看板、工作站、聊天、内容审核、知识库与执行状态等关键交互。
- 推进前后端实现、工作流建模、数据结构与实时事件协作。
- 根据实际使用和验收反馈迭代功能，并维护需求、设计与验收文档。
- 使用 AI 工具辅助开发；需求判断、方案取舍、验收标准与最终质量由我负责。

### 解决的问题

内容生成通常跨越多个工具和角色。单次生成结果难以管理上下文、审核意见、返工版本和最终交付。本项目以任务为中心组织这些环节，让团队能看到当前进度、负责人、待确认内容和历史过程。

## 给面试官：产品与工程设计

### 两条独立工作流

- **电商新品上架**：需求对接 → 卖点文案 → 主图设计 → 详情图设计 → 主管校对 → 交付完成。文案、主图和详情图设有人工确认点；图片支持逐张审核；主管可将问题回退到相关阶段。
- **小红书种草笔记**：选题策划 → 笔记撰写 → 首图设计 → 内页设计 → 主管校对 → 交付完成。首图与内页分阶段生成，选题、文案和图片分别经过确认。
- 两条工作流共享任务、Agent、事件和交付物基础类型，同时保留各自的阶段、提示上下文与业务表单。

### 核心设计判断

1. **把生成过程建模为可控工作流**：阶段、条件边、确认点、返工和回退由图定义表达，避免把业务推进逻辑散落在界面按钮中。
2. **让人工判断成为流程状态**：产出进入待确认后，只有明确采纳才继续；打回会记录决定并触发返工。
3. **任务状态与实时协作分层**：Fastify 提供 HTTP API，WebSocket 推送任务、执行和聊天事件，React 工作台据此更新界面。
4. **知识库与生产工作流解耦**：知识资料可以被任务只读引用；知识库不可用时，任务流程仍可独立运行。
5. **为外部模型调用保留可运行的降级路径**：配置本地模型渠道时调用兼容接口；未配置时使用内置演示响应，便于本地体验流程。

  U[用户与任务资料] --> F[React 工作台]

~~~

### 技术栈

- **前端**：React 19、TypeScript、Vite 6、Tailwind CSS v4
- **后端**：Node.js、Fastify 5、WebSocket
- **数据**：SQLite（Node.js 内置 `node:sqlite`，WAL 模式）
- **共享层**：pnpm workspace 中的 `@workbench/shared`，维护前后端共用类型、事件协议与工作流定义
- **工程文档**：OpenSpec 需求与变更说明，配套设计规范、验收清单和示例知识库

## 功能概览

- 多工作流任务看板、筛选、任务详情与执行事件
- Agent 工作站、角色聊天、模型渠道与技能/文件挂载设置
- 文案与图片交付物、版本记录、人工审核、返工和导出
- 电商新品上架与小红书图文内容生成
- 知识库浏览、任务资料引用、知识图谱与热点内容
- 可选内存沙盒：用演示数据体验主要界面，不连接真实后端，也不保存刷新后的操作

## 本地运行完整应用

### 环境要求

- Node.js 22 或更高版本
- pnpm 9 或更高版本

### 安装依赖

在仓库根目录运行：

~~~powershell
pnpm install --ignore-scripts
~~~

### 配置模型渠道（可选）

复制 `backend/.env.local.example` 为 `backend/.env.local`，再填写本地使用的渠道信息。该文件已被 Git 忽略，API Key 不应写入源码、README 或提交记录。

不配置模型渠道也可以启动应用并查看流程；需要真实模型生成时，请在本机配置对应的文本、生图或视觉审核渠道。

### 启动后端

在第一个终端运行：

~~~powershell
Set-Location backend
.\node_modules\.bin\tsx.cmd watch src/index.ts
~~~

后端默认监听 `4311`。

### 启动前端

在第二个终端运行：

~~~powershell
Set-Location frontend
.\node_modules\.bin\vite.cmd
~~~

打开 http://127.0.0.1:4310。

## 浏览器沙盒演示

在已启动的前端地址后添加 `?sandbox=1`，例如：

http://127.0.0.1:4310/?sandbox=1

沙盒使用内存演示数据，操作不会写入后端数据库；刷新后恢复初始演示状态。普通地址不带该参数时，前端连接本地 Fastify 后端。
