## 零、核心判断

先说结论：**这个项目最大的视觉资产不是它的 UI，是它正在跑的数据。**

多 Agent 工作台天然拥有别人没有的「活内容」——Agent 之间的任务交接、推理过程、溯源链路、热点发现、成本累积。现在这些全被压成了静态卡片和表格。

> **改造存量**能让界面变顺滑；**把活数据可视化**才能让它变酷炫，而且**别人抄不走**——这是产品独有的内容，不是通用模板。

基于这个判断，增量资产的价值排序如下（越靠上越值得做）：

| 梯队 | 方向 | 为什么值 | 依赖数据是否已有 |
|---|---|---|---|
| 一 | **实时运行态可视化** | 产品独有、不可复制、最能体现"这是个系统在工作" | ✅ 已有（WS 推送、事件时间线、Agent 状态） |
| 二 | **数据可视化层** | 目前几乎空白，是最大的视觉洼地 | ✅ 已有（成本、溯源、热点、统计） |
| 三 | **专业工具感组件** | 桌面工具的高级感标志 | ⚠️ 需要新建交互层 |
| 四 | **去 AI 味的质感层** | 低成本、立刻消除"塑料光滑感" | ✅ 无需数据 |

## 一、实时运行态可视化（最高价值）

### A1 · Agent 活动总线 Live Activity Bus

- **现状**：`features/observability/ObservabilityView.tsx:151` 是 4 张静态 Agent 卡片；忙碌状态只有一个 `qs-dot.busy` 脉冲（`index.css:252`）
- **新增**：一条贯穿全局的实时活动流，展示「哪个 Agent 正在接手哪个任务的哪个阶段」，数据包在节点间沿连线流动
- **为什么酷**：这是整个产品最核心的叙事，现在完全没被讲出来
- **放置建议**：
  - 轻量版：TopBar 下方一条 6px 活动带（滚动胶囊，参考 transitions.dev 的 Banner stacking）
  - 完整版：Agent 状态页中央舞台，做成横向流水线
- **参考**：
  - [GodUI · Agent Flow](https://godui.design/docs/components/ai/agent-flow)（可拖拽 Agent 节点图 + 数据包流动，你的调研已列为「直接用」）
  - [transitions.dev · Reasoning stream](https://transitions.dev/)（推理流滚动）
  - [transitions.dev · Matrix dot loader](https://transitions.dev/)（16 点矩阵四模式脉冲，适合无任务时的待机态）

### A2 · 执行流水线（替代一维阶段条）

- **现状**：`ui.tsx:84-115` 的 `StageFlow` 是静态圆点 + 连线，无动效；`StageStepper`（`TaskDetailView.tsx:197`）有呼吸环但仍是线性呈现
- **新增**：横向流水线，**正在执行的节点有沿连线流动的数据包**；某阶段失败时连线由紫转红并向该节点收敛；重跑（`ReworkPanel`）时整条链 animate back
- **参考**：
  - [GodUI · Agent Timeline](https://godui.design/docs/components/ai/agent-timeline)（步骤时间线 + 状态 + 可折叠工具输出）
  - [transitions.dev · Transaction processing](https://transitions.dev/)（处理中的连续状态）
  - Vercel Build Logs 的逐行推进样式

### A3 · 思考流替代转圈 Spinner

- **现状**：`ui.tsx:238-245` 的 `Spinner` 是「转圈 + 处理中…」
- **新增**：实时显示 Agent **正在调用什么工具、检索了哪份知识、生成到第几段**，逐行流式滚动，**每次只保留两行**（避免刷屏）
- **为什么重要**：转圈是最廉价的等待表述，也是最容易被感知为"AI 敷衍"的元素。换成真实推理过程后，等待本身变成内容
- **参考**：
  - [transitions.dev · Thinking states](https://transitions.dev/)（状态行微光后切换到下一个）
  - [transitions.dev · Reasoning stream](https://transitions.dev/)（推理两行滚动）
  - [transitions.dev · Streaming text](https://transitions.dev/)（词语通过软交叉模糊逐个解析）
  - [transitions.dev · Image generation placeholder](https://transitions.dev/)（点噪声唤醒后解析成图像 —— 对「平平」生图场景极度贴合）

### A4 · 内容生成占位（生图场景专属）

- **场景**：设计 Agent「平平」生成商品图时
- **新增**：不用灰色骨架条，用**点噪声逐步解析成最终图像**（异步 +blur 收敛）
- **参考**：[transitions.dev · Image generation placeholder](https://transitions.dev/)

## 二、数据可视化层（最大视觉洼地）

现在整个项目只有 `KnowledgeGraphView` 的 canvas 力导向图这一个「有技术含量」的视觉。

### B1 · 溯源链路图 Provenance Graph

- **现状**：`TaskDetailView.tsx:682` 有 `ProvenancePanel`，但应是列表形式；「溯源命中验证」是项目的核心能力之一
- **新增**：把「结论 → 引用片段 → 原始文档」做成**可逐层展开的链路图**，点击节点回溯到源文件
- **为什么值**：溯源是这个产品的差异化能力，值得给它一个专属视觉，而不是塞在侧栏列表里
- **参考**：现有 `KnowledgeGraphView` 的 canvas 力导向实现可复用（`graphCanvas.ts`）

### B2 · 迷你图表层 Sparklines

- **现状**：`ObservabilityView.tsx:219` 的统计卡、`TaskDetailView.tsx:849` 的 `CostCard` 全是静态数字
- **新增**：给以下数据配 SVG 迷你图（**不引入第三方图表库**）：
  - 成本累积曲线（CostCard）
  - 任务吞吐 / 平均耗时趋势
  - Agent 负载均衡
  - 热点热度随时间的衰减
- **参考**：纯 SVG polyline + `tabular-nums` 等宽数字即可

### B3 · 知识星图前置

- **现状**：`KnowledgeGraphView` 藏在 `#/knowledge-graph` 路由里，是全站唯一有物理模拟的视觉
- **新增**：把星图的**精简版**作为知识库主页的概览区，或做成Moda l 的「全局溯源视图」
- **理由**：好东西要放到用户看得见的地方

## 三、专业工具感组件

### C1 · 命令面板 Command Palette（Cmd+K） ★★★

- **现状**：项目**完全没有**。项目无路由库、无全局搜索入口，`useWorkbench.tsx` 的 hash 路由也没暴露命令层
- **新增**：Cmd/Ctrl+K 唤起，支持跳转视图、搜索任务、执行 Agent 操作、切换知识库
- **为什么值**：这是 **Linear / Raycast / Superhuman 的招牌交互**，是「专业桌面工具」最强的单点信号。已拉取的品牌参考里 `raycast.md` 和 `superhuman.md` 的整个产品叙事都建立在这上面
- **参考**：
  - `参考资料/raycast.md`、`参考资料/superhuman.md`（已下载到 `动效方案资料/`）
  - [GodUI · Prompt Composer](https://godui.design/docs/components/ai/prompt-composer)（auto-grow + 附件 chips + 发送→停止 morph，可与命令面板合并成「AI 输入框」）

### C2 · 底部状态条 Status Bar

- **新增**：底部常驻一条，显示 WS 连接状态、当前活跃 Agent 数、待办数、本次会话耗时
- **参考**：规划表 G3 已提到「All systems operational」式实时状态条（PORTO ROCHA）

### C3 · 空状态重构 ★ AI 味重灾区

- **现状**：`ui.tsx:253-270` 的 `Empty` 只有一行灰字「暂无数据」，`py-10 text-center` —— 这是全站最像 AI 占位符的地方
- **新增**：为 6 个视图各配一个**专属**空状态：图标 + 主文案 + 副文案（说明为什么空）+ 单 CTA（下一步能做什么）
  - 例如知识库空态 → 「还没有资料」+「拖入文件或连接数据源来建立知识库」+ CTA「上传文档」
- **可选**：用 GPT-Image 生成一组线稿插画，但注意必须保持 Quiet Signal 的线稿感，**不能用彩色 3D 插画**
- **参考**：规划表 §1 第 10 项已锁定 [Aceternity Empty States](https://ui.aceternity.com/blocks/empty-states) 与 [21st.dev empty-state 分类](https://21st.dev/community/components/s/empty-state)

### C4 · 品牌化启动 / 加载首屏

- **现状**：`index.html` 直接挂载 `#root`，打开是从白到内容的硬切；有 skeleton 但无品牌启动态
- **新增**：一个极简的品牌入场（位移分散 className + 一句产品定义 + 加载进度），300–500ms 后让位
- **注意**：必须极短，且 `prefers-reduced-motion` 下直接跳过。宁可不做也不要做成一个等待 2 秒的开场动画

## 四、去 AI 味的质感层（低成本、高回报）

这四项**都不违反红线**（不是渐变、不是光晕、不是粒子、不是 3D），但能显著消除「AI 生成的塑料光滑感」。

| 编号 | 手段 | 做法 | 针对的症状 |
|---|---|---|---|
| D1 | **微噪点 grain** | 全站叠一层 opacity 2–4% 的 SVG feTurbulence 噪点，或 1px 平铺的 noise PNG | 消除纯色平面的塑料感，这是「AI 生成图」最典型的破绽 |
| D2 | **发丝线工程网格** | 背景铺极淡的 1px 网格线（`rgba(0,0,0,0.03)`），间隔 8px 对齐 `--space` 基数 | 增加工程感与精密度暗示；与已采用的 Interfere 型（G1）一致 |
| D3 | **等宽数字对齐** | 所有数字 / ID / 时间戳 / 金额统一 `font-family: var(--font-mono)` + `font-variant-numeric: tabular-nums` | 数字跳动是廉价感的直接来源；tabular-nums 让列表数字严格右对齐成列 |
| D4 | **1px 内高光** | 卡片与 inset 区域用 `box-shadow: inset 0 1px 0 rgba(255,255,255,0.6)` | 模拟受光边缘，比 glow 克制得多；适合 input / 凹槽 / 表格头 |

> D1 与 D2 可以只选一个先做。**推荐先做 D3**（改动最小、收益最确定：只看板列表 + 表格就有 20+ 处数字）。

## 五、明确不能做（红线重申）

延续 `组件视效规划表.md` §0 与 `godui-动效组件库调研.md` §三 的禁用清单：

❌ 玻璃拟态 / 毛玻璃　❌ 渐变光晕 / Aurora　❌ 粒子背景 / 光束　❌ 3D 按钮 / 3D tilt　❌ 光标跟随特效　❌ Confetti / Border Beam / Spotlight　❌ 文字渐变特效　❌ 滚动视差炫技

> **注意 transitions.dev 上有两个模式虽然很酷但对本项目是陷阱**：`3D tilt`（带 cursor glare）和 `Confetti burst`。它们在这份红线下不可用，不要因为它们酷就加进来 —— 它们是营销落地页的语言，不是工作平台的语言。

## 六、建议排期

| 批次 | 内容 | 理由 |
|---|---|---|
| 第 1 批 | **D3 等宽数字** + **C3 空状态重构** | 改动小、收益确定、立刻可验收 |
| 第 2 批 | **A3 思考流** + **A4 生图占位** | 替换掉的 Spinner 是全站最高频的低质元素；且直接回应「降低 AI 味」 |
| 第 3 批 | **A2 执行流水线** + **B2 Sparklines** | 中等工作量，视觉回报明显 |
| 第 4 批 | **C1 命令面板** | 工作量最大，但单点提升最强，建议单独排一个迭代 |
| 第 5 批 | **A1 活动总线** + **B1 溯源链路图** | 需要后端 WS 配合，放到后端 ready 之后 |
| 穿插 | **D1/D2 质感层** + `refs` 全局生效 | 随时可做，建议挑加进来验证方向对不对 |

> 存量改造（上一份方案的 P0/P1/P2）与本文的增量资产可以并行推进，互不依赖。若只能选一个先做，**建议先做增量中的 A3 + 存量中的 P0-2/P0-3** —— 一个解决「内容有东西看」，一个解决「出现方式有节奏」。
