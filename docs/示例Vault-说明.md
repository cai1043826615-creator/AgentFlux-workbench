# 示例 Vault（知识库板块 B 的演示 / 复现数据）

这是一个**最小可用的 Obsidian Markdown Vault**，用于试用与复现「知识库管理系统」的全部能力：
目录/标签浏览、中文全文检索、知识星图、任务关联资料注入。

> 本说明文件刻意放在 `docs/` 下、**不在 Vault 目录内**：Vault 内任何 `.md` 都会被索引，
> 说明文档混进去会污染演示数据（实测会让文档数从 5 变成 6）。

## 内容

```
10_raw/products/磁吸充电宝.md     产品资料（规格/卖点/电池/定价）· 标签 产品/充电/主推
10_raw/products/桌面折叠支架.md   产品资料 · 标签 产品/配件
wiki/brand/品牌规范.md            品牌视觉与文案规范（含广告法禁用词） · 标签 品牌/规范
wiki/brand/文案语气指南.md        标题/卖点/禁用词写法 · 标签 品牌/文案
30_topics/双11大促节奏.md         大促时间节点与素材节奏 · 标签 运营/大促
.obsidian/workspace.md           故意放在默认排除目录内，用于验证「排除目录不进入索引」
```

刻意包含的设计点：
- **`[[wiki链接]]` 与相对路径链接** → 用于验证知识星图的文档间关系边
- **共享标签**（如 `充电` 同时出现在两篇文档） → 用于验证标签关系与「共享标签的文档」
- **`#7C3AED` 色值** → 用于验证不会被误判为行内标签
- **长/短中文关键词**（`充电宝` 3 字 vs `磁吸` 2 字） → 分别命中 FTS5 trigram 与 LIKE 兜底
- **具体规格数字**（10000mAh / 15W / 198g / GB 31241） → 用于验证「资料注入后 Agent 不再编造参数」

## 如何使用

1. 启动后端与前端（见根目录 `README.md`）
2. 左栏「知识库」→「连接设置」→ Vault 根目录填**本目录的绝对路径**，例如：

   ```
   <仓库根>/docs/示例Vault
   ```

3. 保存并索引 → 应看到 5 篇文档、9 个标签、3 个目录、16 条关联边（`.obsidian` 被默认排除）

也可以改用环境变量兜底配置：

```powershell
$env:WORKBENCH_VAULT_ROOT = "<仓库根>\docs\示例Vault"
```

## 注意

- 工作台对 Vault 是**只读**接入：不会修改、删除或移动本目录内任何文件。
- 若要验证「关联资料失效」降级，可临时改掉某个文档的章节标题或删除文件，再重建索引。
