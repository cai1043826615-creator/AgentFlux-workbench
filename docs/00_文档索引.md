## 命名规范

**新文件命名格式**：`序号_文件名_日期后缀`

| 部分 | 规则 | 示例 |
|---|---|---|
| `序号` | 两位数字，按逻辑顺序或时间排列（`01_`、`02_`…），便于目录内排序 | `01_` |
| `文件名` | 中文简明描述 | `UI设计与组件规范` |
| `日期` | `MMDD` 四位 | `0908` |
| `失效后缀` | 仅归档文件需要 | `_已失效` / `_部分被取代` |

**示例**：
- 规范类：`01_UI设计与组件规范_0916.md`
- 设计类：`03_增量视觉资产方案_0913.md`
- 归档类：`03_并行开发边界约定_0913_已失效.md`

> 无序号的历史文件（如 `开发日志记录.md`、`开发注意事项.md`）保持原名不动，避免破坏既有引用。

## 维护约定

1. **改规则 → 改项目根 `AGENTS.md`**，不要只改 docs 下的文档。
2. **新增文档**：按上述命名规范放入对应目录，并**同步更新本索引**。
3. **文档失效**：移入 `归档/`，文件名加失效后缀，并在 `归档/00_归档说明.md` 登记失效时间与原因。
4. **移动文档后**：必须全局搜索并修正引用路径（`grep -rn "旧路径"`），本项目历史上多次因路径失效导致找不到文档。
