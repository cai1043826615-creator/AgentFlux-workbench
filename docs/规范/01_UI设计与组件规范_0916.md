## §1 定位与使用

### 1.1 这份规范解决什么问题

行业调研（见 `docs/调研/05_设计规范治理工具调研_0916.md`）给出了一句关键诊断：

> **"Even with a well documented design system, drift begins immediately."**
> （即使设计系统文档写得再好，漂移立刻开始）

本项目实证了这一点：`v1.0` 规范写了 304 行，但 AI 在整个开发过程中**一次都没打开过**，导致：
- 11 处 `rounded-[3px]`（规范要求 4px）
- 10 处硬编码 `#fff`（规范要求用令牌）
- lightbox 组件被重复实现 2 遍

**因此本规范的设计原则是**：
1. **关键约束不靠本文档承载** → 摘要卡内嵌进 `AGENTS.md`（每轮必载）
2. **本文档只做"查阅"用途** → 需要完整细节时才打开
3. **能机器校验的必须机器校验** → 不依赖人的自觉

### 1.2 谁该读、何时读

| 角色 | 何时读本文件 |
|---|---|
| AI 代理 | **仅在需要完整令牌表 / 组件清单 / 新增流程时**（日常约束见 `AGENTS.md` 摘要卡） |
| 开发者 | 新建组件前（§4）、改视觉前（§2）、做 UI 验收前（§8） |
| 评审者 | 按 §8 验收清单逐项核对 |

### 1.3 规范的四个部分（与工具链对应）

| 部分 | 内容 | 对应工具 |
|---|---|---|
| **§2 令牌** | Design Tokens（单一事实来源） | `index.css @theme` |
| **§3-§4 组件** | 组件注册表 + 新增流程 | 机械校验（组件使用检测） |
| **§5-§7 场景与风格** | 非 CSS 场景、动效、风格红线 | 机械校验（色值/间距规则） |

## §2 Design Tokens（单一事实来源）

> **唯一来源**：`frontend/src/index.css` 的 `@theme` 块。
> **强制**：所有视觉值必须从此处取令牌，**禁止就地写裸值**。
> 新增令牌的流程见 §4.4。

### 2.1 颜色令牌（17 个）

| 用途 | 令牌 | 值 |
|---|---|---|
| 页面底 | `--color-canvas` | `#fafafa` |
| 卡片/面板面 | `--color-surface` | `#ffffff` |
| **反色前景**（深底上的白字） | `--color-inverse` | `#ffffff` |
| 内收区 | `--color-sunken` | `#f4f4f5` |
| 正文主色 | `--color-ink` | `#0a0a0a` |
| 次级文字 | `--color-ink-soft` | `#52525b` |
| 弱化文字 | `--color-ink-faint` | `#a1a1aa` |
| 默认描边 | `--color-line` | `#ececee` |
| 强调描边 | `--color-line-strong` | `#dcdce0` |
| **主色**（紫，稀疏用） | `--color-signal` | `#7c3aed` |
| 主色悬停 | `--color-signal-strong` | `#6d28d9` |
| 主色浅底 | `--color-signal-soft` | `#f3effe` |
| 成功 | `--color-ok` / `--color-ok-soft` | `#15803d` / `#ecfdf3` |
| 警告 | `--color-warn` / `--color-warn-soft` | `#b45309` / `#fff8e6` |
| 危险 | `--color-danger` / `--color-danger-soft` | `#b91c1c` / `#fef2f2` |

**`--color-inverse` 与 `--color-surface` 值相同但语义不同**：
- `surface` = 「面」（卡片背景）
- `inverse` = 「反色前景」（深底上的白字/白图标）
- **不要互换使用**——语义错位会让后续调整（如加暗色模式）无法区分。

### 2.2 几何令牌（圆角只有两档）

| 场景 | 值 | 说明 |
|---|---|---|
| 大结构（卡片、面板、模态框） | `0` | `.qs-card` 直角，体现"编辑性"气质 |
| 小控件（按钮、输入框、小表面） | `4px` | 唯一允许的非零圆角 |
| `pill`（999px） | 仅限极短状态标签 | 需符合 QS pill 边界，不得泛滥 |

**❌ 禁止**：`3px` / `6px` / `8px` / `10px` 等任何中间值。

### 2.3 间距令牌（4px 基数）

`--space-1` ~ `--space-6` = **4 / 8 / 12 / 16 / 20 / 24 px**

**规则**：所有间距必须是 4 的倍数；优先引用令牌而非写裸值。
**允许的例外**：为对齐既有设计而微调的 1-2px 偏移（需 `ui-rules-ignore` 注明）。

### 2.4 字体令牌

| 角色 | 令牌 | 字体栈 |
|---|---|---|
| 标题 | `--font-display` | Noto Serif SC / Songti SC（衬线，编辑感） |
| 正文 | `--font-body` | Noto Sans SC / Microsoft YaHei |
| 元信息 | `--font-mono` | JetBrains Mono（数字/代码/时间戳） |

### 2.5 动效令牌

| 项 | 令牌 | 值 |
|---|---|---|
| 快（微反馈） | `--dur-fast` | 160ms |
| 标准（常规过渡） | `--dur-standard` | 220ms |
| 缓慢（大块动效） | `--dur-deliberate` | 300ms |
| 缓动曲线 | `--ease-standard` | `cubic-bezier(0.22, 1, 0.36, 1)` |

**强制**：所有动效必须含 `prefers-reduced-motion` 降级（`index.css` 已全局处理，新动效不得绕过）。

### 2.6 阴影策略

**默认无阴影。** 仅以下场景允许：
- 真实抬升的浮层：Toast、Modal、下拉菜单、搜索建议
- 卡片 hover 微抬升（`.qs-interactive`，克制幅度）

**实现方式**：浮层阴影可用 `rgba()` 语义色，但**必须加 `ui-rules-ignore` 注明理由**。

### 2.7 令牌与代码的同步

**问题**：本项目历史上出现过"规范文档写的令牌与 `index.css` 实际值不一致"。
**约束**：改令牌**只改 `index.css`**，本文档 §2 是镜像，两边必须同步。
**未来增强**：可加脚本校验"本文档 §2 的表格 vs `index.css @theme`"一致性（见 §9.3）。

## §4 新增组件流程

> **这是本规范最重要的流程章节**，直接针对「避免一个功能出一堆组件」。
> 违反本流程 = 制造技术债。

### 4.1 强制前置三问

新建组件前，**必须**在代码文件头写下这三个问题的答案：

```tsx
/**
 * 【新增组件前置声明】
 * 1. 现有组件为何不行：<具体说明查过 §3 注册表，如"Modal 不支持嵌套滚动"是原因>
 * 2. 复用范围：<预计在哪些地方使用，至少 2 处才值得抽象>
 * 3. 是否应提升为通用组件：是 / 否（说明理由）
 */
```

**如果第 1 问答不出来** → 说明没查注册表，**回去查**。
**如果第 2 问只有 1 处** → 按 §4.3 处理（不抽，写内联 + 注释说明）。

### 4.2 判定标准：什么时候该抽组件

| 情形 | 决策 |
|---|---|
| 同一模式**已重复 2 处以上** | ✅ **必须抽** |
| 明确**将随新工作流页面复用** | ✅ 抽（即使当前只有 1 处） |
| 仅 1 处使用，且无复用预期 | ❌ **不抽**（内联 + 注释说明为何不抽） |
| 已有组件**功能覆盖 80%** | ✅ 扩展既有组件（加 prop），**不要新建** |

### 4.3 放置位置

```
frontend/src/components/
├── ui.tsx              # 基础原子（按钮/输入/卡片/Modal等）
├── Toast.tsx           # 反馈类（独立文件）
├── DocPreviewModal.tsx # 特定业务组件
└── <新组件>.tsx        # 新组件（先放这里，数量多了再按 §4.5 分层）
```

**规则**：新组件**一律放 `components/`**，**不得散落在 `features/` 下**。
**例外**：仅服务于单一 feature 且明确不通用 → 可留在该 feature 内，但需在前置声明中说明。

### 4.4 新增令牌流程

若需要**新的视觉值**（新颜色/新尺寸）：

1. **先检查** §2 现有令牌是否已覆盖（很可能只是没找对）
2. **确需新增** → 在 `index.css` 的 `@theme` 中加令牌（命名遵循 `--color-*` / `--space-*` 语义）
3. **同步更新** §2 的表格（镜像）
4. **不得**就地写裸值

### 4.5 组件分层（规模增长后启用）

当前组件少（13 个），**保持扁平**。当 `components/` 超过 20 个文件时，再按此分层：

```
components/
├── ui/        # 基础原子
├── feedback/  # 反馈类（Toast/StatusDot）
├── layout/    # 布局类（Tabs/Timeline/Dropdown）
├── workflow/  # 工作流类（StageStepper/StatusTag）
├── data/      # 数据展示（DataTable/StatCard）
├── media/     # 媒体类（ImageThumb/ImagePreview）
└── chat/      # 会话类（MessageBubble）
```

**不要提前分层**——空目录是负担。

## §5 非 CSS 渲染场景（Canvas / SVG）

> 本项目 `frontend/src/features/knowledge/graphCanvas.ts` 使用 Canvas 2D 绘制知识星图。
> Canvas 的 `ctx.fillStyle` **只接受具体色值，无法直接使用 `var(--color-*)`**。

### 5.1 正确做法：JS 读取 CSS 变量（方案 A，已采纳）

```ts
/** 令牌桥接：从 CSS 变量读取设计令牌（Canvas 无法直接用 var()） */
const cssVar = (name: string) =>
  getComputedStyle(document.documentElement).getPropertyValue(name).trim();

const TOKEN = {
  signal: cssVar('--color-signal'),
  ink: cssVar('--color-ink'),
  // ...
};
```

**要求**：
- 令牌读取**集中在文件顶部**，不散落在绘制逻辑里
- 需处理 `document` 不可用的场景（SSR/测试）
- 若变量读取失败，回退到硬编码值并 `console.warn`

### 5.2 透明度处理

Canvas 需要半透明色时，用 `globalAlpha` 或 `color-mix()` 的结果，**不要手写 `rgba()`**：

```ts
ctx.globalAlpha = 0.5;
ctx.fillStyle = TOKEN.signal;
```

### 5.3 其他非 CSS 场景

| 场景 | 做法 |
|---|---|
| SVG `fill` / `stroke` | 可直接用 `var(--color-*)`（SVG 支持 CSS 变量） |
| 内联 `style` | 可用 `var(--color-*)` |
| 第三方图表库 | 传令牌值（用 §5.1 的 `cssVar`） |

## §6 动效规范

### 6.1 时长与曲线

见 §2.5。**原则**：微反馈用 `fast`，常规过渡用 `standard`，大块变化用 `deliberate`。

### 6.2 允许的动效模式（克制）

| 模式 | 用途 | 实现 |
|---|---|---|
| 卡片 hover 微抬升 | 可点击卡 | `.qs-interactive` |
| 当前步骤呼吸光圈 | 阶段条当前节点 | `qs-step-pulse` |
| 按钮 loading 旋转 | 异步操作 | `qs-btn-spinner` |
| 导航激活指示条 | 左栏当前项 | 2px 主色条 |
| Toast 进入/退出 | 通知 | 淡入淡出 |
| 搜索建议展开 | 输入联想 | 高度/透明度过渡 |

### 6.3 强制要求

1. **必须含 `prefers-reduced-motion` 降级**（`index.css` 已全局关闭，新动效不得绕过）
2. **只动画 `transform` / `opacity` / `filter`**（性能）
3. **禁止无意义循环动效**（除非表示"进行中"状态）
4. **禁止装饰性动画**（如背景粒子、光晕）

## §7 风格红线（禁止项）

### 7.1 绝对禁止

| 禁止 | 原因 |
|---|---|
| **玻璃拟态**（backdrop-blur 营造毛玻璃） | 与"克制企业级"气质冲突 |
| **渐变光晕 / 彩虹渐变** | 同上 |
| **粒子 / 装饰性 3D** | 无功能价值，增加视觉噪音 |
| **层层圆角**（嵌套不同圆角值） | 几何不统一 |
| **卡片墙**（同质卡片满屏堆叠） | 信息层级丢失 |
| **胶囊泛滥**（一切都用 pill） | pill 仅限极短状态标签 |
| **无意义循环动效** | 分散注意力 |
| **emoji 当图标** | 用 `Glyph` 几何图标 |

### 7.2 紫色使用纪律

`--color-signal`（`#7c3aed`）是**焦点色**，不是主题色。

**允许**：当前选中项、主 CTA、关键状态标记、焦点描边
**禁止**：大面积背景、多个同级元素同时用、纯装饰

**判据**：一屏内紫色元素**不应超过 3 处**（除非是密集列表的当前项标记）。

### 7.3 视觉气质

- 大结构**直角**，小控件**4px**（QS Hybrid 几何）
- **默认无阴影**，靠描边与留白建立层次
- 字体：标题**衬线**（编辑感），正文**无衬线**，元信息**等宽**
- 留白充足，**不追求信息密度**

## §8 视效变更验收清单

> **每次 UI 更新（新增功能 / 调整视觉 / 重构组件）完成后，必须逐项核对。**

| # | 检查项 | 命令 | 通过标准 |
|---|---|---|---|

| 2 | 密钥扫描 | `node backend/scripts/check-secrets.mjs --all` | exit 0，0 命中 |
| 3 | 类型检查 | `pnpm typecheck` | 0 error |
| 4 | 前端构建 | `pnpm --filter ./frontend build` | 成功 |

### 8.2 人工检查（逐项确认）

| # | 检查项 | 标准 |
|---|---|---|
| 5 | **令牌合规** | 无硬编码色值；新增视觉值已加进 `@theme` |

| 7 | **新增组件声明** | 若有新组件，已写 §4.1 的三问声明 |
| 8 | **注册表已更新** | 新增组件已加进 §3 表格 |
| 9 | **动效降级** | 新动效含 `prefers-reduced-motion` 处理 |
| 10 | **视觉回归** | 截图对比改动前后，无意外变化 |
| 11 | **响应式** | 窄屏下布局不破（如适用） |

### 8.3 验收记录

重大 UI 变更需在 `docs/改动记录/` 留下记录（含截图），格式参考既有 `04_小红书工作流三轮修复与挂载改造_0914.md`。

## §9 例外机制与违规处理

### 9.1 何时可以例外

**规范允许的例外场景**（无需特殊审批，但要标注）：
- 遮罩类语义色（lightbox 背景遮罩）
- 浮层阴影（Toast / Modal / 下拉）
- 遮罩上的元素配色（半透明白描边/文字）
- 为对齐既有设计微调的 1-2px 偏移

### 9.2 如何标注例外

在该行**或上一行**加注释：

```tsx
// 行尾方式（单行）
style={{ background: 'rgba(0,0,0,0.55)' }} {/* ui-rules-ignore 遮罩语义色，规范允许 */}

/* 上一行方式（JSX 属性等无法行尾注释时） */
/* ui-rules-ignore 浮层阴影：下拉菜单真实抬升，规范允许 */
style={{ boxShadow: '0 4px 12px rgba(10,10,10,0.08)' }}
```

**要求**：`ui-rules-ignore` 后**必须写明理由**，不能空标。

### 9.3 存量基线

历史遗留的违规若暂时不清，**必须显式标注** `ui-rules-ignore 存量基线，待排期清理`，使「真违规」与「已知基线」可区分。

**当前基线**：无（2026-09-16 已清零）。

### 9.4 违规处理流程

1. **提交时被拦** → 按提示修正（**不要用 `--no-verify` 绕过**）
2. **确需例外** → 加 `ui-rules-ignore` + 理由
3. **发现规范本身有问题** → 提规范变更（改本文档 + `AGENTS.md` 摘要卡），**不要就地违反**

## 附：规范变更流程

**本规范是长期文档，变更需留痕**：

| 变更类型 | 流程 |
|---|---|

| **修改规则** | 改本文档 + **同步改 `AGENTS.md` 摘要卡**（两处必须一致） |
