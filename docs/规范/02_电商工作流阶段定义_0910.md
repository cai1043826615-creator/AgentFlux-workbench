# 电商新品上架 · 工作流阶段定义（设计梳理稿）

> 适用场景：多 Agent 协同的电商工作流 Web 工作台
> Agent 岗位：文案 / 设计师 / 主管（校对审阅）/ 人工（拍板）
> 看板 4 列：规划中 / 进行中 / 待确认 / 已完成
> 固定人工确认点（仅 2 个）：卖点文案、产品主图

> **与 OpenSpec 实现模型的一致性说明**（2026-09-08 修订）：本文稿中的「任务已完成 → 自动创建下一阶段任务」为业务流程层面的描述；OpenSpec 实现模型（design.md D2）采用**单任务 + 多阶段 + 看板列**——一个上架任务贯穿全部 6 阶段，`workflow_stage` 字段表示当前节点、`board_column` 字段表示看板列，阶段推进不创建新任务。确认点通过后任务在同一任务内进入下一阶段（列从「待确认」回到「进行中」），终审回退也是同一任务内的节点回退。二者表达同一业务流程，本文稿侧重阶段产出与协作逻辑，design.md 侧重数据与状态机实现。

## 一、推荐方案：6 阶段「电商新品上架」工作流

| # | 阶段 | 负责 Agent | 输入 | 输出（交付物） | 人工确认（确认点） | 主管校对（触发时机） |
|---|------|-----------|------|----------------|--------------------|----------------------|
| 1 | 需求对齐 | 人工 ＋ 文案 | 产品基础资料：品名 / 类目 / 材质 / 规格 / 价格 / 库存、卖点素材、目标平台与人群、参考竞品链接、品牌素材（logo、色值） | 上架需求单（结构化产品信息 ＋ 卖点素材池 ＋ 视觉风格参考） | 否。若需求单关键信息缺失，由文案标注待补项并打回人工补充（走「进行中」内部循环，不占确认点） | 否 |
| 2 | 卖点文案 | 文案（产出）＋ 主管（校对）＋ 人工（拍板） | 上架需求单 | 卖点文案包：商品标题（含平台关键词优化）、核心卖点 5 条、详情页文案大纲、搜索关键词清单 | ✅ 确认点 1。文案完稿 → 主管校对通过 → 任务进入「待确认」；人工通过 → 任务「已完成」并解锁主图设计；驳回 → 附修改意见回「进行中」由文案返工 | ✅ 文案初稿完成后、进入人工确认之前（轻量质检，保证给人工看的是低错误版本） |
| 3 | 主图设计 | 设计师（产出）＋ 主管（校对）＋ 人工（拍板） | 上架需求单 ＋ 已确认卖点文案 | 产品主图组：白底图 ＋ 场景主图（如 1 主图 ＋ 3 副图，按目标平台规格输出） | ✅ 确认点 2。主图交付 → 主管校对通过 → 任务进入「待确认」；人工通过 → 任务「已完成」并解锁详情图；驳回 → 附修改意见回「进行中」由设计师返工 | ✅ 主图初稿完成后、进入人工确认之前（轻量质检：构图、清晰度、卖点呈现） |
| 4 | 详情图设计 | 设计师（产出）＋ 主管（校对） | 上架需求单 ＋ 已确认卖点文案 ＋ 已确认主图 | 详情页长图：卖点图、细节图、参数图、场景图拼接的完整详情页 | 否。按用户约定，本节点不设人工卡点，主管校对通过即进入下一阶段 | ✅ 详情图完成后、流转下一阶段之前（重点核对：文案与图片信息一致性、长图分区完整） |
| 5 | 主管校对 | 主管 | 阶段 2/3/4 全部产出 ＋ 上架需求单 | 校对报告 ＋ 修改意见单（通过放行；发现问题按归属回退对应阶段） | 否。本阶段即「质检总闸」，不重复设人工拍板 | —（本阶段即校对本身，属全量终审） |
| 6 | 交付完成 | 主管（打包）＋ 人工（可选触发上架） | 全部通过产出 ＋ 校对放行单 | 上架资料包：标题 / 关键词 / 文案 / 主图 / 详情长图打包，附多平台规格对照与适配说明 | 否（可选：人工一键「去上架」动作，作为对外发布前的最终确认动作，不设卡点） | ✅ 打包前按交付清单终核对一遍，缺件即补 |

### 阶段说明与协作逻辑

- **分层校对设计**：阶段 2、3 的校对是「轻量质检」（交付前把关，避免低级错误直接暴露给人工）；阶段 5 是「全量终审」（跨产出物一致性：主图与文案信息是否一致、详情图与卖点是否对应、平台合规与规格完整性）。这样既守住两个确认点的质量，又保留一道收尾总闸。
- **两个确认点的看板「待确认」流转**：
  - 产出完成 → 任务移入「待确认」列（状态徽章：待人工确认）。
  - 人工通过 → 任务置为「已完成」，下一阶段任务自动从「规划中」进入「进行中」。
  - 人工驳回 → 任务回「进行中」，评论附修改意见，对应角色（文案 / 设计师）领回返工，改完重新进入「待确认」（可多次循环）。
- **无确认点阶段的流转**：进行中 → 完成后直接「已完成」，自动创建下一阶段任务，全程无需人工干预。
- **终审回退（跨阶段打回）**：阶段 5 发现问题时，按问题归属把对应阶段任务从「已完成」回退到「进行中」重新排期。例：主图信息与文案不符 → 主图设计任务回「进行中」；详情图缺参数分区 → 详情图设计任务回「进行中」。

## 二、各阶段产出一句话描述（供 UI 预览）

| 阶段 | 产出预览（一句话） |
|------|-------------------|
| 1 需求对齐 | 一张「上架需求单」卡片：产品信息、卖点素材池、视觉风格参考要点列表 |
| 2 卖点文案 | 一张「文案包」卡片：标题、5 条核心卖点、详情文案大纲、关键词清单 |
| 3 主图设计 | 一组「主图」缩略图墙（白底图 ＋ 场景图），标注尺寸规格 |
| 4 详情图设计 | 一张「详情长图」预览条，可横向滚动查看卖点 / 细节 / 参数各分区 |
| 5 主管校对 | 一张「校对报告」卡片：问题清单（已通过 / 待修改）与修改意见 |
| 6 交付完成 | 一个「上架资料包」文件清单：标题、关键词、图片、详情长图与平台规格对照表 |

## 三、备选方案（5 阶段，合并视觉设计）

| # | 阶段 | 与推荐方案的差异 |
|---|------|------------------|
| 1 | 需求对齐 | 不变 |
| 2 | 卖点文案（人工拍板） | 不变 |
| 3 | 视觉设计（主图 ＋ 详情图一次承接） | 合并推荐方案的阶段 3、4：主图单独人工拍板，详情图仅主管校对 |
| 4 | 主管校对（终审） | 不变 |
| 5 | 交付完成 | 不变 |

**一句话差异**：把「主图设计」与「详情图设计」合并为单一「视觉设计」阶段——阶段更少（5 个）、设计师可一次统筹整套视觉的风格一致性，但进度条颗粒度变粗，主图拍板后详情图无法独立拆分排期。

（延伸参考：也可反向拆成 7 阶段，把「素材与风格确认」独立成阶段，先锁定风格再开工；适合 SKU 多、视觉返工成本高的团队。）

## 四、总结

推荐方案按「资料 → 文案 → 主图 → 详情图 → 校对 → 归档」的真实上架顺序线性切分，两个确认点恰好落在「卖点文案」与「产品主图」这两个最需要人工把关的产出物上，其余节点自动流转、零人工卡点——既贴合电商团队实际协作习惯，又让进度条每一格都有明确交付物可预览，阶段命名（需求对齐 / 卖点文案 / 主图设计 / 详情图设计 / 主管校对 / 交付完成）非技术用户一眼可懂。
