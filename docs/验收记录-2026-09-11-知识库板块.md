## 三、过程中修复的真实缺陷

1. **知识星图画布空白**（真实缺陷，浏览器验收发现）
   - 现象：进入知识星图，头部显示「节点 14 · 边 16」，但画布全白。
   - 根因：`<canvas>` 仅在数据到达后条件渲染，而绘制循环的 `useEffect` 依赖为 `[simulate, draw]`（两者稳定）→ 首帧 `canvasRef.current` 为 null 时直接 return，数据到达后 effect 不再执行，画布永不绘制。
   - 修复：canvas 元素改用回调 ref 存入 state，绘制循环依赖 `[canvasEl, simulate, draw]`，canvas 挂载后立即绑定。
   - 验证：`getImageData` 统计非透明像素 13813（此前为 0）。

2. **行内标签正则贪婪吞词**（单元测试发现）
   - 现象：`#7C3AED，文案语气克制专业。` 被整段解析为标签，导致「标签数」统计错误（4 而非 3）。
   - 根因：`#([^\s#][^\s]*)` 未排除中文标点。
   - 修复：收紧为 Obsidian 标签合法字符集 `[\u4e00-\u9fa5A-Za-z0-9_][\u4e00-\u9fa5A-Za-z0-9_\-/]*`，并保留十六进制色值守卫。

3. **测试污染本地真实配置**（REST 冒烟测试发现）
   - 现象：关注域配置测试写入 `backend/config/attention.json`，导致二次运行时「默认电商关注域」断言失败。
   - 修复：新增环境变量 `WORKBENCH_ATTENTION_CONFIG` 覆盖配置路径（同时也便于用户迁移配置），测试隔离到临时目录；清理被污染的本地文件。

## 四、关联资料注入复核（真实 LLM · 受控 A/B）

### 实验设计

任务描述刻意**不含任何规格数值**，把产品资料的「产品规格」「电池与安全」两个片段与「品牌规范」整篇挂到任务上；唯一变量是 system prompt 中是否含 `【关联知识库资料】` 段，其余（user 消息、模型、温度）完全相同，走生产代码路径（`buildProducerSystemPrompt` + `callLlm`）。

- 任务 `#8`「轻磁 Pro 磁吸充电宝 新品上架」，平台 天猫
- 描述原文：`写一份电商主图卖点文案和详情页大纲，突出便携与快充。规格参数请以知识库资料为准。`
- 关联 3 份：`产品规格`(片段 122 字符) · `电池与安全`(片段 64 字符) · `品牌规范`(整篇 187 字符)
- system prompt 长度：无注入 1165 字符 → 有注入 1787 字符（+622）

### A/B 产出对比（真实 deepseek-chat）

| 事实（任务描述中不存在） | A 组：不注入 | B 组：注入 3 份资料 |
| --- | --- | --- |
| 容量 | ❌ **编造 `20000mAh`** | ✅ `10000mAh / 37Wh` |
| 重量 | ❌ **编造约 `370g`** | ✅ `198g` |
| 无线输出 | ❌ 未提及 | ✅ `磁吸 15W` |
| 有线输出 | `22.5W`（碰巧猜中） | ✅ `22.5W` |
| 电芯与寿命 | ❌ 未提及 | ✅ `锂聚合物电芯循环寿命 500 次以上` |
| 认证 | ❌ **编造 `3C 认证`** | ✅ `GB 31241 认证` |
| 安全保护 | 泛化描述 | ✅ `过充、过流、过温、短路四重保护` |
| 质保 | ❌ **编造 `18 个月质保`** | 未编造 |

**结论**：不注入时 LLM 会「自信地编造」具体参数（容量、重量、认证、质保全都错），注入后全部规格与 Vault 原文一致——这正是「让产出有据可依」的产品价值，也是本次耦合点存在的意义。
