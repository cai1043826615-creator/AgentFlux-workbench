## 一、工作流结构重排（第二轮验收定案）

### 1.1 XHS 六段结构（最终）

```
选题策划(确认) → 笔记撰写(确认) → 首图设计(确认) → 内页设计(确认) → 主管校对(自动) → 交付完成(自动)
```

- **首图/内页拆成两段**：先只生成 1 张首图，确认后再生成内页图（避免一次生成全废）
- **发布包装删除**：包装并入交付，交付包用「导出交付包」按钮取回
- **主管校对是自动节点**：图文一致性 + 合规双重审核，检出问题沿 rollback 边自动回退
- **交付完成也是自动节点**：校对通过直接归档（方案 a），人工确认点共 4 个
- 电商结构不变（6 段 3 确认点），仅 `deliver` 保持自动

### 1.2 关键防御：归档前置断言

`executor.onStageCompleted` 末段归档前检查事件日志：有 review 类节点的工作流，**未见 REVIEW_PASSED 事件就不允许归档**，自动回退校对节点补做。根因是曾出现库内工作流定义损坏（`detail-image.approvalPoint` 丢失 → 跳过人工确认直通归档）。

### 1.3 启动自检（根治库与代码不一致）

`seed.ts` 新增 `syncBuiltinWorkflow()`：**内置工作流以代码常量为准强制同步**，不一致时覆盖并打日志（`[workbench] 工作流定义与代码不一致，已同步覆盖：xxx`）。

> ⚠️ 运维注意：**改工作流定义后重启后端即自动同步**，无需手工改库；自定义工作流（不在内置表）不受影响。

### 1.4 负责人链路

- 创建任务即预填首段负责人（美美/文案）
- 阶段推进按图节点 `ownerRole` 切换（首图/内页=平平，校对/归档=波波）

### 1.5 配图数量（brief.imageCount）

- 语义 = **总数含首图**：首图固定 1，内页 = N − 1
- 范围 2-7，默认 3；新建任务表单字段名「配图数量」
- 存 `tasks.brief`（JSON），越界/缺失回退默认

### 1.6 生图超时

XHS 与电商（淘宝链路）**统一为 generateImage 默认 180s**（曾收紧 30s，按用户定案同步回）。失败可见化由 runStage（失败原因写卡片）+ 前端 toast 承担。

### 1.7 笔记文案质量（300-500 字）

`produceNote` prompt 重写：300-500 字硬区间、第一人称真实体验、3-5 自然段、1-2 个 emoji 点缀、小红书口语、带 1 个小缺点增可信度、输出前自查字数；`brief` 的人群/产品/内容类型注入 prompt；mock 降级文案同步加长。

## 二、紫条与一键采纳（最终行为）

```
内容卡内逐项「采纳/打回」   ← 原有操作，原样保留
        +
紫条右侧「一键采纳」       ← 纯快捷操作，标准尺寸（85×33），右置
        ↓ 任一方式
全部决策完 → 后端自动推进 → 紫条自动消失（无重复操作）
交付阶段/已交付 → 紫条按钮为「导出交付包」（无"一键"前缀）
```

- 文案（两条工作流统一）：`…全部采纳后自动进入下一阶段；失败可打回重做。`（「急用时可直接一键采纳」已删）
- **显示守卫**：待确认 + 非交付阶段 + 阶段 key 在当前工作流定义里（历史坏任务不显示空操作按钮）
- **修复的关键 bug**：图片阶段一键采纳曾一次 `decide('image','approve')` 不带 imageId → 后端匹配不到图 → 不推进。改为**逐张循环决策**（pending→approve、failed→skip），决策完由后端自动推进

- 电商未产出态改用同款灰态虚线卡（`MutedPlaceholder` 共用）
- Tab 顺序：内容交付（左，默认）→ 任务详情；「任务详情」内「当前阶段：」标题字体统一 `font-display 15px`

### TaskInfoBar 参考图规则（两条工作流统一）

有上传参考图 → 用上传图；没有 → 用 **AI 生成的首图**（电商取 main-image、小红书取 xhs-cover 第一张已生成/已采纳图；failed 自动排除）。统一逻辑在 `shared.tsx` 的 `resolveInfoBarRef()`。

## 四、技能与文件挂载体系（按工作流隔离）

### 4.1 数据与注入

- `agents` 新增 `workflow_files` 列（JSON 分份），与 `workflow_skills` 同构
- 注入：任务执行取**该工作流的技能份 + 文件份**；份缺失回退全局（旧数据零迁移）
- 全局 `skills`/`files` 为各份并集（只读派生视图，路由层自动维护）
- 注入隔离已用探针实证：电商任务只注入电商份文件、小红书只注入小红书份

### 4.2 两级界面职责（scope）

| 界面 | 显示 |
|---|---|
| Agent 设置弹窗（工位栏入口，`scope="workflow"`） | 只显示**当前工作流**那一份（技能 + 文件） |
| Agent 设置弹窗（Agent 状态/知识库入口，`scope="all"` 默认） | 总览：两条工作流 |
| 二级「挂载」弹窗（任何入口） | 永远单工作流：技能目录按分类过滤（电商→电商+通用；小红书→小红书+通用）、文件列表排除已挂到另一条的 |

### 4.3 上传

- 每条工作流标题右侧两个按钮：**[上传技能] [上传文件]**
- 上传技能：`POST /api/agents/skills` → `技能库/<中文分类>/`，索引立即失效重建、立即可挂载、自动挂到发起方
- 上传文件：`POST /api/agents/files` → 知识库收件箱，自动挂到发起方
- **目录名 = 中文展示名本身**（曾映射反成英文 key，已修）

### 4.4 挂载弹窗体验

- 双搜索框统一 176px（缩 20%）、右对齐、框内无提示文案；文件区搜索套用知识库「输入即出候选」全套交互（点选即勾选/已挂可反选/Enter 采纳/Esc 收起/onBlur 延迟 150ms）
- 分类收纳三角（点击整组收起/展开，重开复位）
- 修复吸顶露残行（去滚动容器顶 padding，实测 5 个滚动位缝隙全 0）
- 高度各缩 20%（技能 30vh、文件 24vh）
