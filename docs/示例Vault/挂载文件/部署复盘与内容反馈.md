# 部署复盘与内容反馈

项目：课题分离小红书心理笔记

## Part 1：第一次在别人电脑部署的流程复盘

### Part 1 简介

这一部分主要复盘“第一次在别人电脑上把 XHS-xl + ppt-master 跑通”的全过程。重点不是记录每条命令，而是总结哪些地方最容易卡住、为什么会卡住、当时怎么解决，以及下次换电脑部署前应该先检查什么。

### Part 1 快速概要（含解决方式）

- **输出目录权限卡住**：默认写到 `Administrator` 桌面，但当前账户是 `Benson`，没有写入权限。  
  **解决方式**：先确认当前 Windows 用户名，把输出路径改到当前用户可写目录。

- **Python 不可用**：系统里的 `python.exe` 是 Microsoft Store 占位入口，不是真正解释器。  
  **解决方式**：用 `winget` 安装 Python 3.12，并在脚本里优先使用真实 Python 的绝对路径。

- **依赖缺失**：`ppt-master` 的生图、SVG 预览、PPTX 导出都依赖 Python 包。  
  **解决方式**：安装 `ppt-master/requirements.txt`，并确认 `pip` 可用。

- **API 配置缺失**：第一次生图探活失败，提示没有 `OPENAI_API_KEY`。  
  **解决方式**：创建 `C:\Users\<用户名>\.ppt-master\.env`，写入 `IMAGE_BACKEND`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`。

- **生图 manifest 格式不匹配**：自定义 JSON 不能直接给 `image_gen.py --manifest` 使用。  
  **解决方式**：改成标准 `items` 数组，每项包含 `filename`、`prompt`、`aspect_ratio`、`status`。

- **规划文件结构不被检查器识别**：SVG 本身没问题，但 `design_spec.md/spec_lock.md` 字段不完整。  
  **解决方式**：按 `ppt-master` 标准 I-X 结构写 `design_spec.md`，并补齐 `communication`、`typography`、`page_rhythm` 等关键字段。

- **图片分辨率轻微不足**：底图比例正确，但像素比画布略小，导出时有轻微放大警告。  
  **解决方式**：本次可接受；下次追求更锐利时用 2K 生图或更贴近 `1242x1660` 的尺寸。

### 1. 本次实际流程

这次完整跑通了从文案生成、项目落地、AI 生图、SVG 排版到 PPTX 导出的流程，最终产物是 6 页小红书卡片 PPTX。

实际关键步骤如下：

1. 生成小红书笔记方向和正文，用户锁定为“版本 B + 模型 A + 灰蓝”。
2. 创建项目目录和输出目录。
3. 生成正文 MD、分镜表、`image_prompts.json`、`spec_lock.md`。
4. 安装 Python 3.12 和 `ppt-master` 依赖。
5. 配置图片生成 API。
6. 跑 1 张 `_probe` 小图探活。
7. 批量生成 6 张无字底图。
8. 手写 6 页 SVG，叠加关键句。
9. 跑 first-page 和 final SVG 质量检查。
10. 生成 speaker notes。
11. 执行 `finalize_svg.py` 和 `svg_to_pptx.py` 导出 PPTX。
12. 将成品复制到 `【输出文件】/最终卡片.pptx`。

### 2. 主要卡点

#### 卡点 1：默认输出路径无权限

原默认路径是：

```text
C:\Users\Administrator\Desktop\AI-JUMP\小红书-心理书籍分享
```

但当前账户是 `Benson`，没有权限写入 `Administrator` 桌面，导致创建目录失败。

最终改为：

```text
C:\Users\Benson\Desktop\AI-JUMP\小红书-心理书籍分享
```

注意事项：在别人电脑部署时，第一步先确认当前 Windows 用户名和目标输出目录权限。不要默认写 `Administrator` 桌面。

#### 卡点 2：系统里只有 Microsoft Store 的 Python 占位入口

一开始执行 `python --version` 没有正常输出，`where python` 指向：

```text
C:\Users\Benson\AppData\Local\Microsoft\WindowsApps\python.exe
```

这只是 Windows 的 Store 占位符，不是真正可用的 Python。

解决方式：

```powershell
winget install -e --id Python.Python.3.12 --scope user --accept-package-agreements --accept-source-agreements
```

安装后真实 Python 路径是：

```text
C:\Users\Benson\AppData\Local\Programs\Python\Python312\python.exe
```

注意事项：新装 Python 后，当前终端不一定立刻刷新 PATH。部署脚本里建议直接使用 Python 绝对路径，等新开终端后再用 `python`。

#### 卡点 3：`ppt-master` 依赖需要提前安装

安装 Python 后，还需要安装 `ppt-master` 依赖：

```powershell
python -m pip install --upgrade pip
python -m pip install -r C:\Users\Benson\.codex\skills\ppt-master\requirements.txt
```

注意事项：`python-pptx`、`Pillow`、`requests`、`flask`、`google-genai` 等依赖都在这里。缺依赖会影响生图、SVG 预览、PPTX 导出。

#### 卡点 4：API `.env` 缺失

第一次跑生图探活时失败：

```text
Error: No API key found. Set OPENAI_API_KEY in the current environment or a .env file.
```

最终写入：

```text
C:\Users\Benson\.ppt-master\.env
```

需要包含：

```env
IMAGE_BACKEND=openai
OPENAI_BASE_URL=<服务商 base url>
OPENAI_API_KEY=<本机环境变量或服务商 key>
```

注意事项：不要把 API Key 发在聊天里。已经暴露过的 key，最好任务结束后去服务商后台轮换。

#### 卡点 5：`image_prompts.json` 必须符合 `ppt-master` manifest 格式

一开始的 JSON 是自定义结构，后面发现 `image_gen.py --manifest` 需要标准结构：

```json
{
  "items": [
    {
      "filename": "P01_cover.png",
      "prompt": "...",
      "aspect_ratio": "3:4",
      "status": "Pending"
    }
  ]
}
```

注意事项：每个 item 至少要有 `filename`、`prompt`、`aspect_ratio`、`status`。否则批量生图会失败。

#### 卡点 6：`design_spec.md` 结构必须符合检查器预期

SVG 本身第一次已经通过，但质量检查报错来自规划文件：

```text
design_spec.md must contain ## IX. Content Outline
design_spec.md §IX contains no Slide blocks
spec_lock.md ## communication is missing key line(s): audience
Master export requires spec_lock.md typography rows: title, body
```

解决方式：

- `design_spec.md` 改成 `ppt-master` 标准 I-X 结构。
- `## IX. Content Outline` 下必须写 `#### Slide 01 - ...` 这种页面块。
- `spec_lock.md` 里补齐 `communication.audience`。
- `spec_lock.md` 里补齐 `typography.title` 和 `typography.body`。

注意事项：以后不要只写“能给人看懂”的设计说明，要写检查器能识别的结构。

#### 卡点 7：生图分辨率略低于画布

生图输出是：

```text
1086x1448
```

画布是：

```text
1242x1660
```

比例一致，但导出时会有轻微放大，所以质量检查给出非阻塞警告：

```text
Image is 1086x1448 but displayed at 1242x1660 — may appear blurry
```

注意事项：如果要更精细，建议用 2K 生图或让图片生成尺寸更接近 `1242x1660`。

### 3. 下次部署检查清单

部署前先确认：

- 当前 Windows 用户是谁，输出目录是否可写。
- `python --version` 是否是真 Python，不是 Microsoft Store 占位符。
- `pip` 是否可用。
- `ppt-master` 依赖是否已安装。
- `C:\Users\<用户名>\.ppt-master\.env` 是否存在。
- `.env` 里是否有 `IMAGE_BACKEND`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`。
- 生图前先跑 1 张 `_probe`。
- `image_prompts.json` 是否是标准 manifest。
- `design_spec.md` 是否有标准 I-X 结构。
- `spec_lock.md` 是否包含 `canvas`、`mode`、`communication`、`colors`、`typography`、`page_rhythm`。
- 导出后检查 PPTX 页数和输出文件大小。

### 4. 建议沉淀成固定部署脚本

可以沉淀一个 `setup-check.ps1`，专门做这些事：

- 检查 Python 是否真实可用。
- 检查 `pip` 和依赖。
- 检查 `.env` 是否存在但不打印 key。
- 检查输出目录权限。
- 检查 `image_prompts.json` schema。
- 检查 `design_spec.md` 标题结构。

这样下次换电脑部署时，先跑检查脚本，再进入正式生图和导出，会少踩很多坑。

## Part 2：作为读者看文案，为什么会觉得 AI 味重

### Part 2 简介

这一部分只从读者视角看文案，不评价技术流程。核心问题是：这篇“课题分离”文案逻辑顺、语气温柔，但读起来更像标准心理号内容，而不像一个具体的人从真实生活里长出来的表达。所以“AI 味重”的根源不是句子不美，而是太顺、太正确、太缺少真实生活的摩擦感。

### Part 2 快速概要（含解决方式）

- **开头太标准**：`以前我很怕别人不开心` 是正确表达，但缺少具体场景。  
  **解决方式**：用一个真实瞬间开头，比如“拒绝同事后盯着聊天框看了十分钟”。

- **金句太密，生活太少**：连续输出漂亮句子，会像 AI 在提炼观点。  
  **解决方式**：每 1 句金句前放 2-3 个生活细节，让观点从场景里长出来。

- **概念出现太早**：第三段就讲《被讨厌的勇气》和“课题分离”，容易进入知识解释模式。  
  **解决方式**：先写内耗过程，再让“课题分离”作为答案浮出来。

- **治愈模板词过多**：`亲爱的`、`慢慢来`、`回到自己身边` 等词容易显得熟练但不私人。  
  **解决方式**：少用抽象安慰，多写具体动作，比如“我没有再补发解释，把手机扣在桌上”。

- **文章太正确，缺少犹豫**：现在像一个已经想明白的人在劝别人。  
  **解决方式**：加入删了又写、想解释、害怕关系变尴尬等拧巴过程。

- **标题偏方法号**：`别再替别人的情绪买单了` 有力，但真人感弱。  
  **解决方式**：换成带动作和情境的标题，例如 `读懂课题分离后，我删掉了那段解释`。

- **最优修改方向**：不要把文章写成“解释课题分离是什么”。  
  **解决方式**：改成“我终于不再为别人的沉默写小作文”，用故事带出概念。

### 1. 我的第一感受

这篇“课题分离”的文案是顺的，也温柔，逻辑没有问题。

但作为读者，我读完以后会觉得：它像一篇很标准的心理号文案，而不像一个具体的人刚刚经历过什么。

它能安慰人，但记忆点不够强。它把概念讲清楚了，却没有让我看见“这个概念是怎么从生活里长出来的”。

### 2. AI 味主要来自哪里

#### 问题 1：开头太标准了

原文开头是：

```text
以前我很怕别人不开心。
```

这句话成立，但太像心理内容的通用开场。它直接给结论，没有给场景。

读者更容易被具体场景带进去，比如：

```text
上周五，我拒绝了同事一个临时需求。
消息发出去后，我盯着聊天框看了十分钟。
对方只回了一个“好”，我却开始反复想：
是不是我太冷漠了。
```

这种写法有时间、动作、聊天框、停顿。读者会觉得“这是一个人真的发生过的事”。

#### 问题 2：金句太密，生活太少

原文里有很多漂亮句子：

```text
有些情绪，真的不是你的功课。
真正亲密的关系，装得下拒绝，也装得下沉默。
你可以在乎别人，也可以不为别人的每一种情绪负责。
```

这些句子都不错，但连续出现时，会像“AI 在提炼金句”。读者会被安慰，但不一定相信背后有真实经验。

竞品文本的优势是：它先写“毕业以后”“不好不坏的工作”“差不多的城市”“周末去学陶艺”“独自旅行去海边”“换了一份完全不同领域的工作”。这些细节不是金句，但它们让文章有身体感。

建议：每 1 句金句前，至少放 2-3 个具体生活细节。

#### 问题 3：概念出现太早

原文第三段就出现：

```text
后来读《被讨厌的勇气》，才第一次听见“课题分离”这个词。
```

这样会让文章很快进入“知识解释模式”。

竞品文本的方式是先让情绪走一段，再用书里的句子点亮。读者先进入状态，再接受观点。

建议：不要太早说“课题分离”。可以先写一次具体内耗，写到读者点头，再引出概念。

#### 问题 4：“亲爱的”“慢慢来”“回到自己身边”有模板感

这些词本身温柔，但在小红书心理内容里已经很常见：

```text
亲爱的
慢慢来
世界没有塌下来
回到了自己身边
```

读者反馈 AI 味重，很可能不是因为某一句错了，而是这些词组合起来太像治愈模板。

建议：少用泛化安慰，多用具体动作收束。

例如把：

```text
你也终于回到了自己身边。
```

改成：

```text
那天晚上，我没有再补发一大段解释。
手机扣在桌上，我第一次睡得很早。
```

这比抽象总结更像真人。

#### 问题 5：文章太“正确”，缺少犹豫和拧巴

真人表达通常不是一路顺滑的。竞品里有：

```text
可，真的就要这样日复一日吗？我思考了很久。
折腾是真的，可那种真切地活着的感觉也是真的。
```

它有犹豫，有自问，也承认代价。

我们的文案更像已经想明白的人在安慰别人，少了“我也曾经想不明白”的过程。

建议加入一点不完美：

```text
我知道道理是一回事。
真的不解释，又是另一回事。
那天我删了三次对话框。
最后只留下两个字：好的。
```

### 3. 竞品文本值得学的地方

只看 `笔记内容.txt`，竞品有几个很强的点：

1. 它不是一上来讲道理，而是先讲“我被稳定困住”的生活状态。
2. 它有连续的人生动作：毕业、工作、城市、陶艺、旅行、换领域。
3. 它引用名句，但名句不是摆设，后面会接自己的理解。
4. 它承认变化不是一夜完成的。
5. 它的结尾不是“你应该怎样”，而是“我已经学会了回答：好啊，可以试试。”

这让文章像一个人在复盘自己的生活，不像一个账号在解释观点。

### 4. 我建议这篇“课题分离”改成什么方向

不要把核心定位成：

```text
解释课题分离是什么。
```

建议改成：

```text
我终于不再为别人的沉默写小作文。
```

也就是说，先讲一个人际关系里的真实场景，再让“课题分离”成为后面浮出来的答案。

可以按这个结构改：

1. 一个具体场景：拒绝同事、朋友不回消息、家人不高兴、恋人沉默。
2. 自己当时的身体反应：盯手机、胃发紧、开始解释、删了又写。
3. 过去的惯性：只要别人不开心，我就觉得是我的错。
4. 读到《被讨厌的勇气》：课题分离不是冷漠，而是分清谁承担结果。
5. 回到那个场景：我没有再解释，我也没有坏掉。
6. 收束：边界不是少爱别人，是终于不再丢下自己。

### 5. 可替换标题方向

现在标题：

```text
别再替别人的情绪买单了
```

问题是有点像方法号标题，力度有，但真人感弱。

可以换成：

- 我终于不再为别人的沉默写小作文
- 那天以后，我少解释了很多
- 别人的不开心，不一定是我的错
- 我不再把每一次冷场都怪到自己身上
- 读懂课题分离后，我删掉了那段解释

其中我更推荐：

```text
读懂课题分离后，我删掉了那段解释
```

它既有书籍概念，又有具体动作，读者更容易点进去。

### 6. 一段示范改写

下面不是最终稿，只是示范“少一点 AI 味，多一点真人感”的方向：

```text
那天晚上，我拒绝了一个临时需求。

消息发出去以后，我开始反复看手机。
对方只回了一个“好”，我却已经在脑子里写完了三版解释。

我怕她觉得我不够热心。
怕关系变尴尬。
也怕自己看起来很冷漠。

后来我读《被讨厌的勇气》，才第一次明白：
原来不是所有情绪，都要由我来安放。

我是否真诚表达，是我的课题。
她怎么理解我，是她的课题。

这句话听起来很简单。
但那天，我真的靠它停了下来。

我没有再补发一大段话。
也没有把那个“好”翻来覆去地解读。

只是把手机扣在桌上，
去洗了个热水澡。

那一刻我才知道，
边界不是少爱别人，
是终于没有为了被喜欢，
又一次丢下自己。
```

### 7. 最核心的修改建议

如果只改一件事：把“心理学解释”改成“我经历过的一件小事”。

如果只删一类词：删掉过于常见的治愈模板词，比如“亲爱的”“慢慢来”“回到自己身边”。

如果只保留一句金句：保留这句就够了：

```text
边界不是少爱别人，是终于不再丢下自己。
```

这句比“你可以在乎别人，也可以不为别人的每一种情绪负责”更像人话，也更有转发感。
