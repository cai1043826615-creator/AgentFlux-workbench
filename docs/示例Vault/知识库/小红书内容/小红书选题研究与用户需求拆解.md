# 小红书选题研究与用户需求拆解

## 选题目标
找到真实用户正在处理的问题，而不是先选一个流行词再强行套商品。选题应有明确读者、使用场景、信息缺口和可交付的帮助。商品只在确实能支持主题时出现。

## 研究输入
来源可包括公开笔记、平台搜索联想、经授权的客服咨询、站内评论和用户访谈。记录采集日期、关键词、样本链接/编号、账号身份、样本量、观察范围及限制；去除个人信息。公开样本只说明该样本表达了什么，不代表全部用户。

## 需求拆解表
| 观察到的原话/现象 | 来源与日期 | 用户任务 | 当前障碍 | 可提供的信息 | 商品是否相关 | 证据/限制 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

将观察分为购买前认知、对比选择、使用方法、适配疑问、使用后的维护和场景灵感。把同义问题合并后，保留不同人群、设备和环境的差异。

## 选题评分
用 1–5 评估：真实问题清晰度、资料可得性、独特信息价值、受众匹配、可视化可能性、商品相关性、合规风险。评分只是团队排期工具，不能称为平台流量预测。资料少但风险高的选题先补研究，不急于发布。

## 输出
每个选题输出一句话主张、目标读者、问题证据、笔记承诺、可用资料、需补事实、形式建议、风险检查、发布日期和负责人。若不能给出可靠信息价值，改为待研究或放弃。关联[[小红书内容规范]]、[[笔记标题开头与叙事结构]]和[[真实场景笔记结构模板库]]。

## 样本质量控制
采样时区分搜索结果页、热门笔记、普通笔记、商业合作内容和评论；记录排序方式和采样日期。不要只选高赞笔记后推断大众需求。引用评论时去标识化，不能公开用户账号和私人信息。观察到的表达分成“问题事实、个人偏好、产品反馈、猜测/情绪”，不同类型不能放在同一证据层级。

## 选题评审会
每个选题用一页卡片说明：读者是谁、问题有什么样本、内容给出什么新信息、已有资料够不够、商品为什么相关、哪些结论暂时不能说、发布后的观察指标是什么。内容负责人确认价值，产品负责人确认事实，账号负责人确认身份和形式。没有资料支撑的问题，不因热点热度高而进入生产。

## 从搜索到问题的记录范例
保存用户使用的原始搜索词及其上下文，再归并成可回答的问题。例如不同用户使用“买前看什么”“怎么确认适不适合”等表达，可能都指向适配判断，但不能仅凭词相近就合并成同一购买需求。记录原始样本和合并理由，方便产品负责人审查。

## 研究停止条件
当连续新增样本不再改变问题类别、已有资料能支撑回答、账号适用边界清楚时，可进入脚本阶段；如果新样本仍引入不同 SKU、条件或高风险问题，则继续研究。停止条件是团队的工作记录，不表示用户问题已经被普遍覆盖。
## 访谈与评论样本整理
采集公开问题时只保存完成分析所需的文本片段、链接、日期和上下文，遮蔽昵称、订单号等个人信息。记录这是搜索建议、评论、售后问题还是团队访谈，避免把不同来源混为同一用户群。归纳需求时先保留原话，再写团队解释及证据，不将少数个案描述为普遍现象。

候选题进入脚本前，确认读者能带走一个明确判断或操作方法；写出回答所需的事实、尚缺的资料、可能误解和不适合覆盖的人群。若选题只依赖热词、没有商品相关帮助或无法取得可信证据，进入观察池而不是生产队列。每轮研究保留淘汰原因，后续出现新证据时可重新评估。
## 选题评审的通过条件
评审时请选题负责人用一句话说出“谁在什么情境下遇到什么问题”，再指出将提供的可执行帮助、证据位置和不覆盖范围。其他成员尝试提出一个反例或边界案例；若脚本无法准确回答，缩小选题范围或退回研究。评审结论记录通过、改写、待资料或淘汰及理由，避免口头决定丢失。
