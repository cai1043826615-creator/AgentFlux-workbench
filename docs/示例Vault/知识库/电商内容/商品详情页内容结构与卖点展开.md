# 商品详情页内容结构与卖点展开

## 页面任务
帮助消费者完成认出商品、理解差异、判断适配、评估风险、完成购买的决策。每屏回答一个问题；顺序服务于购买判断，不是平均铺满所有功能。页面与后台属性、实物和其他渠道一致。

## 推荐结构
1. 首屏识别：准确品名、核心价值和商品外观，不做夸大承诺。
2. 需求场景：展示真实可复现的情境，解释产品实际如何参与。
3. 核心卖点：挑选有证据的重点，按重要性排列。
4. 功能结构：解释部件、连接、操作和使用步骤，只描述当前 SKU。
5. 适配限制：兼容尺寸、使用条件、注意事项和不适用情形，放在相关卖点附近。
6. 规格包装：写明单位、测量口径、变体差异和清晰装箱清单。
7. 售后交易：以当前渠道后台的保修、退换、配送和活动规则为准。
8. 购买前检查：提醒核对型号、尺寸、接口、颜色、配件等易选错字段。

## 卖点展开
按“已核验事实 → 适用条件 → 用户问题 → 可感知帮助 → 证据呈现 → 限定/例外”展开。若证据只证明具备某功能，不要加效率、舒适、耐用或结果改善。证据可使用真实结构图、规格表、对应测试图或操作步骤，不以图标暗示无证认证。

## 图文协作
每个模块设一个标题和一个主信息。标题给结论，正文解释证据或步骤，小字放补充条件，不用小字否认醒目标题。数字、单位、图像和文字都要对应 SKU。移动端先保证阅读顺序和可读性，避免小字压在复杂背景上。

## 常见问题模块
只收录客服、评论和退货原因中的真实问题，按适配、使用、规格、配件、售后和价格分组。问题和答复标注来源及适用 SKU。没有官方答复的事项设为待确认，不能让模型臆造政策。

## 验收
核对商品身份、信息顺序、证据、条件可见性、图文和后台一致性、售后时效、促销日期、移动端可读性与版本号。图片完成后按[[视觉制作与质检规范]]复核，发布前按[[电商内容规范]]检查渠道规则。

## 模块写作卡
每个模块交付：本屏决策问题、用户已有认知、主标题、正文、图像动作、事实证据、适配限制、移动端阅读顺序、审核人。建议制作一条信息线：识别商品 → 说明核心理由 → 解释如何工作 → 判断是否适合自己 → 核对规格和服务。遇到用户疑问时，调整其对应模块而非继续加一屏口号。

## 页面逻辑验收
把页面标题和图片顺序单独列出，只读标题能否看懂整体购买逻辑？若同一卖点连续出现多次，保留证据最强、表达最清楚的一处。把所有限制文字抽出来检查是否被孤立放在末屏。把详情页与后台属性并排核对，确保重要参数、包装和售后没有冲突。页面改版后再检查移动端裁切及关键文字是否被遮挡。
## 页面信息顺序评审
评审人从首次接触商品的用户视角顺序阅读：识别商品与变体、理解核心用途、判断规格和适配、查看包装与使用条件、确认交易和售后。每个模块先写它回答的问题，再核对证据是否直接支持答案。不要为了视觉完整把所有卖点塞入首屏；对于会影响适配或安全判断的限制，应与对应卖点邻近展示。

## 页面变更影响
修改标题或首图后，检查搜索结果、广告落地页和社媒引流文案是否仍一致；规格或包装更新后，检查属性后台、详情页、客服问答及图像文字。记录旧页面截图、新版本号、生效时间和回滚条件。若页面模块由平台自动拼接，必须预览真实线上组合，不能仅凭设计稿判断用户最终看到的顺序。
## 页面内容的证据索引
为核心参数、适配描述、材质、包装数量、功能步骤和限制分别设置事实编号，在交付索引中映射到页面模块。页面审核抽取每句影响购买判断的话，确认其对应证据仍适用于当前 SKU。没有证据编号的句子要么补齐资料，要么改为不含该主张的表达。模块顺序调整后再次检查限制条件是否仍紧邻对应卖点。
