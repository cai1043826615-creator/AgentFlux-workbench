# 商品问答与购买异议处理

## 收集与分类
从真实客服工单、售前咨询、评论、退货原因和用户访谈抽取问题。去除个人身份信息，保留 SKU、日期、渠道、问题原文、频次、决策阶段和可查记录。模拟问句不可标为用户原声。

问题分类：商品身份；设备/尺寸适配；功能与操作；质量、材质和测试；价格、活动与交易；安装维护与售后。按决策影响排序。高频疑问可能说明页面没说清，应先检查标题、属性和详情，而不是只在末尾加 FAQ。

## 回答结构
1. 直接说明可以、不可以或需要核实。
2. 标明适用 SKU 和必要条件。
3. 提供证据、页面字段或操作步骤。
4. 清楚说明未覆盖情形和查询路径。
5. 价格、促销、售后仅使用当前生效规则。

骨架：针对某具体型号，在已确认条件下支持某功能。若设备或场景未覆盖，请先提供必要信息，核验后再答复。

## 风险边界
不以“放心”“绝对没问题”代替适配核验；不把单一客服经验推广到所有 SKU；不承诺资料中没有的质保、退款、赔付或发货时限；不暴露订单、地址、手机号和聊天截图；不将模型推测包装成官方结论。

## 处理优先级
按安全/适配风险、购买决策影响、问题频次、影响 SKU 数量排序。一次安全或规格误导可能比多条低风险泛问更重要。将问题标记为“页面缺信息、产品待确认、平台交易咨询、售后个案、用户个人体验”，不同类型分配给不同负责人，避免 AI 直接答复超出权限的问题。

## 答复样例
适配未知：“目前没有覆盖你这款设备的适配记录，请提供设备型号和保护壳情况，我们先核对，不建议仅凭接口外观判断。”
活动未知：“活动规则以你所在店铺当前页面为准；我们暂未拿到该时段审批信息，因此不先承诺价格或赠品。”
资料明确：“当前 SKU 包装清单列有 A、B 两项；如果你购买的是其他颜色/套装，请以对应变体页面为准。”
所有公开回复在发布前检查是否泄漏订单信息，是否承诺了尚未批准的处理结果。
## 问答发布审核
建立问题库时区分公共信息与订单个案；公共答复可以解释已经核验的尺寸、功能、限制和包装，个案问题交官方客服。答案首句直接回应问题，随后给条件、依据或下一步，不复制与问题无关的卖点。涉及兼容性时要求具体设备型号、版本、保护壳和使用条件；在测试记录未覆盖前，明确说尚未核实。

定期检查问答是否对应当前 SKU 和页面版本，标注最后核验日期。停售、改版、政策变化或重复投诉触发复核。AI 草稿不得自动发布，也不得要求用户在公开问答里留下电话、地址或订单号；发现可能的安全问题时升级质量团队而非只给操作建议。
## 典型升级演练
用户问“能不能用”时先确认设备和使用条件；用户报告异常发热、结构损坏或疑似人身/财产风险时，不让普通内容回复替代质量处置；用户追问退款、补偿或物流时转店铺官方客服。升级消息只包含必要信息和平台内链接，说明已采取的临时措施及责任人。公开答复避免要求用户暴露订单与联系方式。
## 答案版本控制
平台问答变更后记录旧答复、更新原因、事实依据和复核日期。若后台仍显示旧内容或无法编辑，建立跟踪项并升级处理，不以本地 FAQ 已更新作为结案。
