# 内容效果回收与迭代记录

## 复盘原则
区分内容产出、曝光、互动、点击、成交、退货和客服问题。不要把相关性说成因果；记录平台、统计口径、时间窗、投放预算、受众和内容版本。平台后台数据与第三方工具估算分开标注，未取得的数据标为未覆盖。

## 单条内容复盘
| 字段 | 记录 |
|---|---|
| 内容编号、平台、SKU、版本 |  |
| 发布时间、观察窗口、账号身份 |  |

| 订单/转化/售后指标与归因口径 |  |
| 用户问题与评论主题 |  |
| 本次修改因素 |  |
| 其他同步变化与限制 |  |
| 结论置信度、下一步实验 |  |

## 解释流程
先确认数据定义和时间窗口，再比较同平台相近内容；标出价格、投放、季节、账号状态、库存等可能影响因素。只有一次样本时，把结论写成观察而非规律。A/B 对比尽量一次更改一个主变量，提前确定观察指标和停止条件。

## 从反馈回到内容
高频疑问更新 FAQ、标题或详情结构；适配误解反馈产品事实卡；画面误读反馈 Brief 和视觉规范；点击高但退货或投诉增加时，优先检查承诺和适配信息，不单看点击。事实变化必须先更新底座，再派生渠道内容。

保留失败版本和原因，禁止只留表现好的截图而丢失样本上下文。关联[[电商内容规范]]、[[小红书选题研究与用户需求拆解]]和[[商品问答与购买异议处理]]。

## 指标解释词典
曝光/展示、阅读、停留、点击、收藏、评论、加购、订单、退款和投诉分别记录平台定义。统计粒度可能因平台更新而变化，引用指标时保存后台截图或导出日期。广告流量与自然流量分开；促销期和常规期分开。估算转化或外部监测不与平台成交数据混为一谈。

## 决策记录
观察到变化 → 检查样本和口径 → 列出同时变化因素 → 提出一个可验证假设 → 设计单变量改动 → 设定时间窗和停止条件 → 回收数据 → 记录未覆盖。样本少或口径不一致时只记录描述性现象，不给因果结论。不能为了提高点击而忽略退货、投诉和适配误解。

## 一次复盘的结论格式
“观察到什么”列事实和来源；“可能解释”列推测及替代解释；“已验证内容”列实际对照；“未覆盖”列缺失数据；“下次动作”列负责人、版本和时间。把来源记录与结论分开，团队成员可以复核分析是否合理。

## 不可比场景
新品冷启动和成熟商品、不同平台、不同促销、不同流量来源、不同观察期的数据不能直接相减。遇到结构变化，重新建立基线。把短期高互动写成长期内容规律前，应有足够复现记录和明确适用边界。
## 复盘数据字典
每次记录先定义指标名称、分子分母、统计窗口、数据后台、归因方式和是否包含付费流量。曝光、点击、停留、收藏、咨询、转化、退款各自回答不同问题，不能用一个指标替代内容质量或用户满意度。保存原始导出日期和筛选条件；平台口径更新时标注版本，必要时重建基线。

## 迭代优先级
优先修复事实错误、适配误解、过期权益和严重可读性问题；其次解决用户反复问到且资料充分的空白；最后再优化标题、构图等表现变量。每项优化绑定具体假设和观察周期，避免同一轮同时改标题、图片、价格和投放。结论注明是否复现、替代解释、后续负责人和复查日期，未达到样本要求时保留为观察项。
## 异常数据处理
数据突然归零、跳升或与后台总量不一致时，先确认采集时间、时区、过滤器、归因更新和平台延迟；保存原始导出，不用手工补数。区分内容表现变化与投放、价格、库存、平台展示变化。无法确定原因时写出待核实假设和所需数据来源，等补齐后再解释，不把时间上的同时发生直接写成因果。
