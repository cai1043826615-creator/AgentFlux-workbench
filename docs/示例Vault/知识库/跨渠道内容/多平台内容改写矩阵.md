# 多平台内容改写矩阵

## 共用底座与渠道改写
共用底座是已核验的商品事实、授权素材、品牌表达和有效交易信息。每次改写只复用底座，不直接复制旧平台成稿，因为标题、版位、用户意图、商业披露和字段要求可能不同。

| 维度 | 电商商品页 | 小红书内容 |
|---|---|---|
| 用户任务 | 判断商品属性、适配与交易条件 | 学习、比较、理解场景或获取经验 |
| 主信息 | 商品身份和可核验购买理由 | 真实问题与有用信息 |
| 结构 | 标题/属性/卖点/详情/交易信息 | 标题/开头/叙事/图片/互动 |
| 事实要求 | 与商品后台、SKU、价格和库存一致 | 与事实底座、真实体验和披露一致 |
| 素材 | 版位清晰、规格/部件/包装准确 | 真实且有授权，不能伪装用户体验 |
| 变化频率 | 属性与活动可能高频更新 | 规则、账号状态与内容主题需持续复核 |

## 改写步骤
1. 从事实底座挑选本渠道需要的事实，剔除无关字段。
2. 明确该渠道的用户问题和可交付价值。
3. 重写开头、信息排序、长度、图像和行动提示。
4. 单独复核平台格式、类目、披露、促销和导流规则。
5. 保存平台版本与共同事实卡的版本关联。

## 禁止的跨用方式
不得把小红书真实体验语气搬到品牌官方账号并暗示真实消费者；不得将电商促销机制照搬到笔记而遗漏条件；不得将平台特定的标题、图片和标签限制推断为其他平台规则；不得从某平台审核通过推断其他平台合规。

每次发布后分别记录平台表现，避免合并成无法解释的总指标。参照[[电商内容规范]]、[[小红书内容规范]]和[[商品事实与宣称证据总则]]。

## 同一事实的改写示例
共用事实先写为“已核验结构/功能及适用条件”。电商页用清楚的商品属性和决策信息回答“这是什么、是否适配、交易条件是什么”；小红书笔记从真实用户问题起笔，解释选择或使用过程并标明商品关系。两类内容都保留同一 SKU 证据编号，但开头、节奏、图片顺序和行动提示不同。

## 渠道变体管理
| 资产编号 | 事实卡版本 | 平台/账号 | 标题版本 | 素材版本 | 披露/条件复核 | 状态 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

事实卡升级时先查所有活跃变体；渠道规则变化只更新受影响版本并留存旧版。不得把某平台后台通过审核当作其他平台可直接使用的证明。
## 渠道差异评审表
每个版本至少对照目标用户、搜索/发现方式、内容长度、商品组件、商业披露、禁用表达、视觉尺寸、行动提示和审核流程。共用事实可复用，但语气、顺序、标题和素材需要按平台重新设计。一个平台的审批结果、推荐机制或创作者经验不自动适用于另一平台。

## 发布映射检查
为每条母稿分配唯一编号，派生稿关联母稿版本、事实卡版本和素材版本；逐个确认文案没有携带其他渠道的专属入口、价格或按钮说明。审核者在各平台预览成稿，确认商品卡、标签、链接和字幕最终呈现方式。平台规则或页面组件变化后，仅将受影响版本标记待复核，并记录复核日期和责任人。
## 改写实例记录
母稿先保留商品事实和判断条件。电商版本按购买决策组织规格、包装、使用限制和交易信息；小红书版本围绕具体问题组织过程、经验边界和清晰的商品关系。逐句标记哪些来自共同事实、哪些是平台专属信息。若同一场景陈述只在某平台有真实记录，不能直接复制到另一渠道当作普遍体验。
