# 单 SKU 内容矩阵与批量生产

## 规划目的
围绕同一 SKU 组织不同决策问题的内容，提升素材复用效率，同时防止同一卖点机械重复。矩阵规划不代替平台规则和事实审核；每个资产仍应指向已核验事实及适用渠道。

## 矩阵字段
| 用户阶段 | 用户问题 | 可用证据 | 电商资产 | 小红书选题 | 视觉素材 | 待补资料 | 发布版本 |
|---|---|---|---|---|---|---|---|
| 发现 | 这是什么/适合谁 |  |  |  |  |  |  |
| 考虑 | 有什么差异/如何使用 |  |  |  |  |  |  |
| 选择 | 是否适配/包含什么 |  |  |  |  |  |  |
| 购买 | 价格/优惠/服务是什么 |  |  |  |  |  |  |
| 使用 | 如何安装、维护或排障 |  |  |  |  |  |  |

## 排期方法
先核对事实完整度和高优先级用户问题，再确定每周交付量。将共享素材的主文件和派生版本分开，维护责任人、截止日期、审核状态、平台和失效时间。动态字段如活动价不进入长期通用素材。

## 批量风险控制
批量生成前锁定当前 SKU 清单及每个变体的参数，避免把相邻款式内容互相复制。生成后逐条核验标题、图像、属性和限制，不以抽检替代高风险参数的逐项审核。一次修改产品事实时，检索所有派生内容并更新或下线。

关联[[AI内容生成任务Brief与交接单]]、[[商品事实与宣称证据总则]]及渠道规范。

## 样例排期骨架
第一组解决商品识别和核心参数；第二组解决适配疑问；第三组展示真实使用或操作；第四组回应购买前常见问题；活动资产单独建立有效期，不混入长期内容。每个资产有独立主信息，批量素材之间避免重复标题和同一构图。计划表给每一行标注事实编号、素材编号、平台和截止时间。

## 批量验收抽检规则
抽检不能只看视觉风格。对 SKU、价格、型号、尺寸、接口、包装和授权这类字段逐项全检；对纯排版可按模板批次抽检，但批次首件、尾件和变更件必须检查。某字段发现一处错，扩大到整批重新检查，并记录错误来自映射表、生成步骤还是人工复制。

## 资产清单控制
为矩阵内每项内容分配资产编号，标注主文件和派生文件。表格筛选当前版本时不应同时出现多个“最终版”。已过活动期或事实过期的内容从复用视图移出，仍保留只读历史。每轮批量制作前检查SKU变体是否新增、停售或换版。

## 例会检查
每周检查等待证据、等待审核、已过期、已发布待回收四类项目。优先清理过期促销和错误规格，避免让新任务继续引用旧素材。若团队容量不足，优先减少重复主题，而不是省略逐条参数复核。
## 主数据和生成分批
在矩阵开始前冻结当前 SKU 主数据版本，包括商品身份、变体关系、批准事实、禁用表达、可用图片和失效信息。按渠道与内容目的拆分批次，避免把一个不确定字段复制到几十条资产。每批先制作一条样稿，经运营、产品和视觉确认字段映射后再扩展，其余变体检查差异字段而非机械复制。

## 变更传播检查
主数据升级时按事实编号反查标题、图片、短视频字幕、FAQ、定时任务和历史模板。记录受影响资产、是否已发布、处理人和截止时间；未找到的引用也记录搜索范围。批量导出后对照清单核对文件数量、SKU、渠道、版本和命名，确保失败文件不会被误认为完成。
## 批次错误抽查处置
一条资产发现错型号、错单位或旧权益时，立即查明该字段是否由模板、数据源或复制步骤带入。扩大检查至同一批全部资产，并抽查相邻批次；修复后记录受影响文件数、线上触点、复验人和防复发动作。不能只改发现的那一张。批次验收保留检查清单与样本依据，方便后续追踪。
